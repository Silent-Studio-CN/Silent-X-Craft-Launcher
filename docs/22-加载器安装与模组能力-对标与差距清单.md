## 1 第一问：MOD 列表是怎么拉的

### 1.1 对照

| 维度 | PCL | HMCL |
| --- | --- | --- |
| 数据源 | **双源**：CurseForge + Modrinth 各拉一页再合并（`Modules/Resource/ResourceSearcher.vb:73` CF、`:99` Modrinth） | **一主一辅**：Modrinth 当主库（`addon/repository/ModrinthRemoteAddonRepository.java:112`），CF 另有实现（`CurseForgeRemoteAddonRepository.java:56`） |
| 服务端筛选 | `facets=[…]`（`ResourceSearcher.vb:110`；写法示例就在 `:102` 的注释里） | `List<List<String>> facets`：`project_type:` / `versions:` / `categories:`（`ModrinthRemoteAddonRepository.java:169-179`） |
| 分页 | CF 用 `index=`（offset，`ResourceSearcher.vb:90`）；Modrinth 用 offset/limit | `NetworkUtils.withQuery(PREFIX + "/v2/search", …)`（`:185`） |
| 排序 | CF `sortField=2`（下载量）+ Modrinth `index=relevance` | Modrinth 原生 index |
| 详情 / 版本列表 | 同一功能两套：`ResourceProject.vb:396`（CF）/`:398`（Modrinth）；版本 `ResourceVersion.vb:235`（CF files）/`:256`（Modrinth version） | `ModrinthRemoteAddonRepository.java:405-500` |
| API Key | CurseForge 要 `x-api-key`，**按 URL 主机**注入（`Modules/ModSecret.vb:36`） | 同样按主机注入（`util/io/NetworkUtils.java:174`） |
| **镜像** | **字符串换主机**：`api.modrinth.com → mod.mcimirror.top/modrinth`、`api.curseforge.com → mod.mcimirror.top/curseforge`（`Modules/Minecraft/ModDownload.vb:1309-1312`） | **候选注入**：同样的两条映射放进 `BMCLAPIDownloadProvider.java:102,104`，由 `injectURLWithCandidates` 让同一个请求自带第二条路（`ModrinthRemoteAddonRepository.java:185`） |
| 由哈希反查工程 | `/v2/version_files`（`LocalResourceLoaders.vb:137`）+ CF `fingerprints/432`（`:219`） | 同（`addon` 里 `LocalModFile` 一套） |

**一句话**：两边都是「服务端 facet 筛选 + 客户端兜底」，都**给社区资源 API 也配了镜像**（`mod.mcimirror.top`）。我们仓库**连一个模组源都没有**（见 §3 A1）。

### 1.2 「优先匹配已有版本」= 置顶推荐，不是过滤

* PCL：工程详情页给卡片排序的 `CardSorter` 里有一档明确写着 `'置顶`
  （`Pages/PageDownload/Resource/PageDownloadCompDetail.xaml.vb:51-57`，排序链 `:67-101`，末尾 `:101` 用 `Distinct`）。
  **本地已有的版本被排到最前，其余版本照常列出、照常可点** —— 不是「只显示匹配的」。
* HMCL：对应逻辑在**本地文件侧**——`addon/mod/LocalModFile.java:204-205` 按 `gameVersions()` 与 `loaders()` 过滤出
  「这个本地文件能用的版本」，用在**更新检查**里，同样不影响浏览列表。
* 更新检查：PCL 走 Modrinth `/v2/version_files/update_individual`（`LocalResourceLoaders.vb:180`），
  **按发布日期**比大小（不用 semver）。

### 1.3 依赖：只展示，不自动装

* PCL：`PageDownloadCompDetail.xaml.vb:520` 把依赖列表 `Deps.Sort()` 出来给用户看。
* HMCL：依赖是一等公民（`addon/RemoteAddon.java:215,225`、`ModrinthRemoteAddonRepository.java:405-410`），
  但用在**装整合包**时的解析；浏览单个模组只列。
* 两边**都不自动换加载器**：版本与当前实例的加载器不匹配时**静默跳过**该文件，不会反问「要不要顺手装个 Forge」。

### 1.4 同名冲突：学 HMCL，不学 PCL

* PCL：**静默覆盖**（同名文件直接写下去）。
* HMCL：**拦下并改名**（`ui/instances/ModListPage.java:217-244` 的 `LocalModFile[]`，`:290` 的 `rollback(from,to)`
  说明旧文件被留着而不是删掉）。
* **本仓采用 HMCL 口径**：同名先拦、给「改名 / 保留旧文件」的选择。

## 2 第二问：模组加载器有哪几种装法

| 加载器 | HMCL | PCL | 本质 |
| --- | --- | --- | --- |
| Fabric / Quilt | 进程内 patch：只下 profile json 拼进版本 JSON，**不跑安装器**（`download/fabric/FabricVersionList.java:49-55`、`download/quilt/QuiltVersionList.java:49-55`，实现 `QuiltInstallTask.java:53,84-137`） | 支持 Fabric，**没有 Quilt** | 纯元数据 |
| Forge ≤ 1.12（legacy） | jar 里有 `install`+`versionInfo` → 直接解包（`ForgeOldInstallTask.java:93`） | 外判注入器 | 解包 |
| Forge 1.13+ / NeoForge | **installer.jar 只当数据容器 + 进程内重建 + 跑 processors**：`ForgeNewInstallTask.java:124-153`（起 Java）、`:155-185`（每个 output SHA-1）、`:77-110`（全命中即跳过 = 幂等）、`:305-324`（从 jar 拷 maven）、`:356-384`（DOWNLOAD_MOJMAPS 特判） | 外判内置的 `com.bangbang93.ForgeInstaller`（`PCL/ModDownloadLib.vb:948,950`），但**跑之前自己先分析并下好支撑库**（`:1153-1197`） | 重放 processors |
| 新旧分流依据 | **内容判定**：含 `spec` → 新；含 `install`+`versionInfo` → 老；都不是 → 抛异常（`ForgeInstallTask.java:137-155`，本地 jar 同套 `:176-201`） | **版本号启发式**：loader 主版本 ≥ 20 → 注入器（`ModDownloadLib.vb:1150`） | — |
| 成功判据 | 每个 output 的 SHA-1 + 异常 | 只看**末 5 行**有没有 `true`（`ModDownloadLib.vb:1027`），**不看退出码** | — |

**推荐模型（不变）**：HMCL 式 —— *installer.jar 只当数据容器 + 进程内重建 + 只在 profile 声明 `processors` 时逐个执行 + 对声明的 output 做 SHA-1（不匹配即失败，全命中即跳过）*。

### 2.1 FCL（安卓）第三种参照 —— 与 HMCL 同源，但把三件事做实了

FCL 的 `fclcore` 是 **HMCL core 的 fork**（带 HMCL 的 GPL 头、类名一致：`Version`/`DefaultGameRepository`/
`ModManager`/`MaintainTask`/`VersionJsonSaveTask`），`com.tungsten.fcl.ui.*` 才是它自己的安卓 UI。要点：

| 事项 | FCL 怎么做 | 对我们的意义 |
| --- | --- | --- |
| 写盘形态 | **拍平**：`MaintainTask.maintainPreservingPatches`(`fclcore/download/MaintainTask.java:106-111`)= 先 `resolve()`（`Version.java:292` 把 `inheritsFrom` 写死 null）再 `setPatches(...)`；落盘 `VersionJsonSaveTask.java:50-54` → `versions/<id>/<id>.json`。**读盘仍兼容继承式**（`resolve`/`resolvePreservingPatches`） | **正是用户点名要学的形态**：写盘自包含、读盘兼容 —— 我们的实现走同一条（见 `docs/23`） |
| 启动 | 用 `resolve()` 后的**合并对象**（`LauncherHelper.java:147`） | 我们过去**完全不解析继承**（`docs/23` §1 的事故） |
| processors | **跑**：`ForgeNewInstallTask.java:73-179`（`side=client` 过滤 `ForgeNewInstallProfile.java:100-102`），先 Java 8、失败换 17/11/21（`:190-196`）；**跑前按 outputs 幂等跳过**（`:89-122`）、**跑后每个 output 校验 SHA-1**（`:163-177`）；**`data/*.lzma` 只复制不解压**（`:415-427`） | A3 的规格直接照它写；工期不含 LZMA |
| 已安装识别 | `ModDependenciesResolver.java`（**FCL 自研**，无 HMCL 头）：文件名 + `hash → /v2/version_file` 反查项目 id；本体已装跳过、**前置仍装**；只自动装 REQUIRED、BFS 上限 50 | 比 PCL 的"置顶推荐"更进一步；我们做模组时照它 |
| 同名 mod | 下载与导入两条链路都是 **REPLACE_EXISTING 直接覆盖**（`DownloadPage.java:948-950`、`FileDownloadTask.java:227-235`、`ModManager.java:265-271`），无备份/改名/提示 | 与 PCL 一致（HMCL 的"拦下改名"是它 UI 层独有的） |
| 加载器源 | 进程内 patch（Fabric/Quilt/Forge 都是），**不跑安装器** | 我们 方式 A 跑安装器是自研路线（见 `docs/23` §3 的坑） |

## 4 本轮把两个悬案钉死了（含工期修正）

### 4.1 `xz.c` **不支持** `.lzma`（alone 格式）—— 但**根本不需要**（FCL 已证）

> **2026-09-22 更正**：FCL 精读（§7）证明 **HMCL/FCL 跑 Forge processors 时压根不解 `data/*.lzma`** ——

## 8 A3 已落地（2026-09-22）：processors 重放

**为什么它是最要紧的一条**：1.13 以后的 Forge **安装器不再自己装东西**。真正的活是
`install_profile.json` 里那串 processor 干的 —— installertools 拆 MCP 映射、jarsplitter 把原版 jar
拆成 slim + extra、ForgeAutoRenamingTool 按 SRG 重命名、binarypatcher 打二进制补丁。
以前方式 B（解包安装）只做五件事就报"安装成功"，装出来的实例**要么没有客户端主 jar、
要么是没打过补丁的原版**。

**参考实现**：FCL `fclcore/download/forge/ForgeNewInstallTask.java`（ProcessorTask /
parseLiteral / patchDownloadMojangMappingsTask）与 `ForgeNewInstallProfile.java`
（`Datum` / `Processor.isSide`）。逐条对齐，两处**故意不同**写在表里。

| 环节 | FCL | 我们 |
| --- | --- | --- |
| 跑哪几条 | `sides == null \|\| sides.contains("client")` | 同款；**没有 sides 键 = 两侧都跑**，空的 sides 数组 = 都不跑 |
| data 取值 | `Map<String,Datum>`，只取 `client` | 同款，兼容"直接是字符串"的老格式 |
| 值求值 | `parseLiteral`：`[坐标]` / `'字面量'` / `{键}` / 其余当"安装器 zip 里的文件"取到临时目录 | 同款（`sxcl_processor_eval`）；**zip 里没有前导斜杠**，所以查条目之前先去斜杠（FCL 走 zip 文件系统，能直接开绝对路径）—— 这一条是真机前差点漏掉的 |
| 产物幂等 | 先看 outputs：全在且 SHA-1 对 → 跳过（**此时不要求工具 jar 在磁盘上**） | 同款，顺序一模一样（重装前清过 libraries/ 也不会因此失败） |
| 命令行 | `java -cp <classpath…>;<jar> <Main-Class> <args…>`，Main-Class 读 jar 的 MANIFEST.MF | 同款；分隔符 Windows `;` / 其它 `:` |
| 失败重试 | Java 8 → 17 → 11 → 21 | 换**路径**：调用方给的 java → `%JAVA_HOME%/bin/java` → PATH 里的 `java`（"按版本号挑 JRE"那套元数据还没接上来） |
| 跑后校验 | 每个 output 存在 + SHA-1 对，否则删掉再抛 | 同款；错误里带上"期望 / 实际" |
| MOJMAPS | `patchDownloadMojangMappingsTask`：改从版本 JSON 的 `downloads.client_mappings` 下（官方站点在国内常连不上） | 接口留好了（`ctx.download_mappings`）：**调用方没接就照常跑处理器**（官方网络能通照样装完），界面接线排在下一步 |
| LZMA | 不解 `data/*.lzma`，只把文件取出来交给处理器 | 同款 |
| `MINECRAFT_VERSION` | FCL 误写成了 jar 路径 | 给**版本号**（实测 1.20.1 的处理器根本不看它） |

**落点**：

- `include/sxcl/processor.h` + `src/services/modloader/processors.c`：访问器 / 求值 / 幂等 /
  命令拼装 / Java 重试 / 跑后校验；**起进程走 `ctx.run` 回调**，于是日志、超时、取消
  全都是安装流程那一套（同一个 process.h）；
- `installer.c`：方式 B 的顺序变成 **解包 maven/ 与通用 jar → `on_libraries` 下依赖库 →
  重放 processors → 复制原版 jar → 写版本 JSON**（写 JSON 仍是最后一步，"有 JSON"才等于"装完了"）；
  处理器失败 = 这次安装失败，绝不留一份"看着装好、其实没打补丁"的实例；
- `loader.h`：`sxcl_loader_library` 多一个 `url_full`（清单里给的 `downloads.artifact.url`）；
  `collect_libraries` 现在收三处（`libraries[]`、`processors[].classpath[]`、`processors[].jar`），
  并且**优先用清单给的绝对地址** —— 实测 Forge 1.20.1 那 46 条依赖里 jsr305 在
  libraries.minecraft.net、其余在 maven.minecraftforge.net，只按 maven 根地址拼会 404；
- `install.c`：方式 B 的库下载排三条候选（清单给的绝对地址 → 它的镜像
  `sxcl_manifest_mirror_url` → maven 根地址 + 路径），`prefer_mirror` 时镜像排第一，
  与安装器 / 资源对象同一个口径；
- `sxcl-dl loader` 补上 `on_libraries`（以前**没接**，方式 B 等于下不了库）与
  `--extract-install`（跳过安装器 CLI 直接走方式 B —— 既是排查兜底，也是这条路自己的
  端到端验收入口）；新开关 `force_extract_install` 落在 `loader.h`，GUI 暂不暴露。

**验收**：`tests/processor_test.c`（新增，**84 项断言**）：自带一个"只写 stored 条目的最小 ZIP
写入器"造真 jar 夹具（仓库里不放二进制夹具），假 run 回调记录命令行 —— 覆盖 side 过滤 /
求值（`[坐标]`、`'字面量'`、内联 `{键}`、缺键与括号不闭合要报错）/ outputs 幂等
（产物齐了、工具不在也跳过）/ 产物哈希不符要报错并删件 / classpath 与 Main-Class 拼装 /
Java 候选重试 / 取消返回 2 / dry-run 不跑 / data 裸值取文件（含"没给 take_file 就如实报错"）。
