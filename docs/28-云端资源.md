# 28 云端资源清单(我们要在远端挂什么)

面向对象:配云端的人 + 写客户端的人。客户端要拉的**每一样远端资源**都在这份清单里,
不在这份清单里的东西**不许**偷偷加接口。

## 0. 约定

* 基址记作 `${BASE}`(例:`https://sxcl.example.com`),HTTPS。
* 所有请求**超时 5 秒**(清单类 10 秒),**失败不许阻塞启动**:拿不到就按"没有这份数据"走。
* 响应必须是 **UTF-8 JSON**;出错也要是 JSON,不许返回 HTML 错误页(客户端解析不了)。
* 每份文件都要能加 `?t=<unix>` 之类的缓存穿透参数,云端别把 `?t` 当路径。

## 1. P0 —— 没有它现在就是残的

### 1.1 CurseForge 代理 `${BASE}/cf/v1/...`

**为什么**:CF 官方 API 必须带 `x-api-key`。把 key 编进客户端 = 谁都能从 exe 里扒出来;
放服务端则**用户端零配置**(这是我们的死线:永远不让用户配置 CF)。

**契约**

| 客户端请求 | 服务端行为 |
| --- | --- |
| `GET ${BASE}/cf/v1/mods/search?...` | 补 `x-api-key: <服务端环境变量>` 转发到 `https://api.curseforge.com/v1/mods/search?...`,**原样透传响应体与状态码** |
| `GET ${BASE}/cf/v1/mods/{id}` | 同上 |
| `GET ${BASE}/cf/v1/mods/{id}/files?...` | 同上 |
| `POST ${BASE}/cf/v1/mods/files` | 同上(body 原样转发) |
| `POST ${BASE}/cf/v1/fingerprints/432` | 同上 |

* **只允许上面这 5 条路径**(白名单前缀 `/v1/`),其它一律 404 —— 别做成开放代理。
* **硬要求:任何情况下不得把 key 写进响应体或响应头**;不得把 key 回显在错误信息里。
* 缓存建议:`search` 60 秒、`mods/{id}` 1 小时、`files` 5 分钟(按完整查询串做键)。
* 建议同时透传 `Retry-After`(CF 限流时客户端会退避)。
* 客户端行为:代理失败 → 退回第三方镜像 `mod.mcimirror.top` → 都失败就**如实报失败**;
  **绝不拿 Modrinth 的结果冒充 CurseForge**。
* 文件下载(可选,但国内很有用):`${BASE}/cf/files/...` → 302 到 `edge/mediafilez.forgecdn.net`
  (第三方镜像现在就是这么干的,实测能下:302 → 206 `application/java-archive`)。

> key 到位后**先配在这里**,不要先想着编进客户端。

### 1.2 启动器自更新 `${BASE}/launcher/stable.json`

```json
{
  "version": "0.3.0",
  "notes": "一句话",
  "minVersion": "0.2.0",
  "files": {
    "win-x64":     { "url": "${BASE}/launcher/SXCL-0.3.0-win-x64.zip",     "sha256": "...", "size": 12345678 },
    "win-arm64":   { "url": "..." },
    "macos-arm64": { "url": "..." },
    "linux-x64":   { "url": "..." },
    "android-arm64": { "url": "..." }
  }
}
```

* 客户端只读**自己平台那一项**;`sha256` 必填(我们要校验后才装)。
* `minVersion` 之上的强制更新由 1.3 的开关决定,别在这里塞布尔。

### 1.3 公告 + 紧急开关 `${BASE}/launcher/notice.json`

```json
{
  "notices": [ { "id": "n1", "text": "一句话", "level": "info" } ],
  "flags": {
    "disableSources": [],
    "forceUpdate": false,
    "minVersion": "",
    "bedrock": false
  }
}
```

* `notices` 为空 → **主页整块不出现**(不许写"暂无公告")。
* `flags` 是我们留的急停闸:关掉某个下载源、强制更新、基岩版开关(那个预留 toggle)。
* 这份文件**一次请求**拿全,别拆成多个端点。

## 2. P1 —— 国内可达性与稳定性

| 资源 | 路径 | 说明 |
| --- | --- | --- |
| 版本清单缓存 | `${BASE}/meta/version_manifest_v2.json` | 回源 `piston-meta.mojang.com`,缓存 1 小时 |
| 版本 JSON 缓存 | `${BASE}/meta/version/{id}.json` | 同上 |
| 加载器目录 | `${BASE}/meta/loaders/{fabric|quilt|forge|neoforge}.json` | 我们抓好的列表,缓存 10 分钟;**这一步国内最容易卡** |
| Java 运行时 | 见下面 **2.1**(这是要拉的最大一件) | 索引 + 分发包,客户端已经有整套引擎 |

### 2.1 Java 运行时(JRE/JDK) —— 要拉的最大一件

客户端**已经有完整实现**(include/sxcl/jre_hosted.h + src/services/install/java_runtime.c),
只差一个"我们自己的地址"。现在的默认地址是 **GitHub raw**:
`https://raw.githubusercontent.com/Silent-Studio-CN/index/main/SXCL/jre/index.json`,
外加一个 `https://gh-proxy.com/` 镜像前缀 —— 我实测 GitHub raw 在国内时通时不通(刚才直接连不上),
**所以这一件最该搬到你那台 CLOUD 上**。

要放的目录结构(照现有契约,不要自己发明):

    <BASE>/java/index.json                                   # 清单
    <BASE>/java/<component>/<version>/bin-x64.tar.xz          # 桌面 x64
    <BASE>/java/<component>/<version>/bin-arm64.tar.xz        # 桌面 arm64 / macOS
    <BASE>/java/<component>/<version>/bin-arm64-v8a.tar.xz    # 安卓 arm64
    <BASE>/java/<component>/<version>/bin-armeabi-v7a.tar.xz  # 安卓 32 位
    <BASE>/java/<component>/<version>/bin-x86_64.tar.xz       # 安卓 x86_64

* 目录名里的 ABI 必须与客户端的 `sxcl_jre_host_abi()` 一致:x64 / arm64 / arm64-v8a / armeabi-v7a / x86_64。
* **每个文件必须给 size 与 sha256**(字面值;也支持 `.sha256` 侧车 URL 的写法);
  两者都没有时客户端会**明说"没有校验信息"**,不会假装校验过 —— 别让我们落到那一档。
* 需要的主版本(按游戏版本自动选):**JRE 8**(1.7.10 及更早)、**JRE 17**(1.17–1.20.x)、**JRE 21**(1.20.5 起);
  每个主版本 × 每个平台一套。解压后单个 100–200 MB,是带宽大头。
* 可选:`mirror` 字段支持给同一个文件写**第二条候选 URL**(例如"我们的域名 + GitHub 兜底"),客户端按顺序试。
* 清单 schema 的权威定义在 include/sxcl/jre_hosted.h(组件 id / javaMajor / version / files[] / abi / dirKey / shimDir),
  改这层要同步改那里 —— **不要另立一套字段名**。

> 搬过去以后,客户端只要把默认 index 地址指到 `<BASE>/java/index.json` 就行(编译期常量或设置默认值)。
> 设置页那个"index 地址输入框"属于**给用户配置**的东西,和我们的口径冲突,确认后应该删掉、改成内置地址。
| 库/资源镜像 | 暂继续用 `bmclapi2.bangbang93.com` | 我们自己的只做"源顺序表",不全量镜像 |

OptiFine(官网国内不稳且有防盗链,见 docs/22 §17)如果决定自建镜像,再加
`${BASE}/optifine/index.json` + jar 本体。

### 2.2 模组中文名表 `${BASE}/meta/modnames.tsv`（P1，2026-09-27 加）

**为什么**：界面上"某些模组有中文名"不是运行时翻译，是**一张表**（PCL 同形：随包带一张本地表，
有就用中文名、没有就用原名）。随包那份在 `assets/data/modnames.tsv`；云端这份让"换数据源 / 补新模组"
**不用发版**（来源与许可见 `docs/29`、`assets/data/modnames.NOTICE.md`）。

**契约**

| 项 | 值 |
| --- | --- |
| 路径 | `${BASE}/meta/modnames.tsv` |
| 方法 | GET，整份一次拿，超时 **10 秒**（与清单类同档） |
| 编码 | UTF-8，TSV，行尾 `\n`（CRLF 也认；开头的 BOM 也认） |
| 大小 | 现在约 0.9 MB（12497 行）；客户端**上限 32 MiB**，超了直接放弃（当"没更新"） |
| 缓存 | 客户端 `<数据目录>/meta/modnames.tsv`，拿到合格的新版才**原子替换** |
| Content-Type | 建议 `text/tab-separated-values`（客户端不看它，只按内容解析） |

**文件格式**（与随包那份**完全一样**；生成器 `tools/modnames_build.py` 直接产出这样一份）：

```
# sxcl-modnames	1            <- 第一行必须是这个（魔数 + 格式版本），客户端认它才当"我们的表"
# version	20260927           <- 单调递增的整数；**必填**
# count	12497                <- 数据行条数（有效记录数）；**必填**
# sha256	<64 位小写十六进制>   <- **必填**；正文（表头之后第一个数据字节到文件结尾）的 SHA-256
# source	...                  <- 人看的出处
# license	...                  <- 人看的许可
# generated	2026-09-27T08:37:15Z
# columns	slug	cf_id	cf_slug	modid	name_zh	name_en	source	mcmod_id
<slug>\t<cf_id>\t<cf_slug>\t<modid>\t<中文名>\t<原名>\t<来源键>\t<上游编号>
```

* 一行七列（`# columns` 行决定列顺序）；**中文名必须非空**，否则这一行客户端当**坏行跳过并计数**
  （坏行数不静默：`sxcl_modnames_bad_lines`）；
* 云端将来**加列**：加在末尾，并同步改 `# columns` 行 —— 老客户端认不出的列名会忽略那一列，不会崩；
* 键的规范化只有一种：**ASCII 转小写 + 去掉空白与常见标点**；中文按 UTF-8 原样比。
  **别指望客户端做拼音 / 模糊 / 翻译匹配** —— 它只会"整串相等或者没有"。

**客户端行为**（三条全过才换，缺一条都不换）：

1. 是合法的表（表头魔数在）；
2. 表头声明的 `sha256` 与 `count` 与正文**对得上**（**没写这两样 = 直接拒**：云端这份必须带）；
3. `version` 比手上那份**新**。

不满足就**继续用现有那份**，把原因记进日志 —— 404 / 500 / 超时 / 摘要对不上，全都只是"这次不更新"，
**不阻塞启动、不弹窗、不拿随包那份去冒充"已经是最新的"**。

**缓存与失败行为**

* 写：先落 `<缓存目录>/meta/modnames.tsv.part`，校验通过后**原子改名**覆盖正式名；
  **失败时缓存里那份原样不动**（不会留下半截表）；
* 启动时挑表：**校验通过（sha256/条数对得上）且 `version` 比随包新的缓存 → 随包那份**；
  两份都没有 = **空表**（不是错误：查什么都返回原名）；
* 可选优化：客户端可以先用 `Range: bytes=0-4095` 只取表头看 `version`；
  云端**不必**兑现 Range（不兑现客户端就走整表那条路，不会因此判失败）。

**这份文件里不挂什么**

* **不挂中文名以外的任何东西**：没有图标、没有简介、没有下载链接 —— 它是"名字表"，不是资源库；
* **不挂机器翻译**：客户端不审内容，塞进来的东西会被当成真的显示出去；补数据只能来自有出处的人工译名；
* **不挂需要登录 / key 的东西**：匿名可 GET 的静态文件；
* **不需要**分页、内容协商、按版本分包（整份一次读完，0.9 MB）。

## 3. P2 —— 可选

* **崩溃/日志上报** `POST ${BASE}/report`:multipart,一个 zip(我们已有的崩溃取证包),≤5 MB,
  只在用户点了"发送"时上传;端点可关闭。
* **基岩版清单** `${BASE}/meta/bedrock.json`:版本列表 + 校验和(Bedrock 的包在微软 CDN,我们不挂本体)。

## 4. 明确**不**挂的东西

* Mojang 的 assets / libraries 大文件本体(已有 BMCLAPI,别浪费带宽)。
* 游戏本体 jar(同上)。
* Modrinth 的文件(官方直连就通,镜像反而绕远)。

## 5. 需要云端同学确认的三件事

1. `${BASE}` 到底是什么?HTTPS 证书有没有?
2. **只能放静态文件,还是能跑一个小服务**(读环境变量里的密钥 + 做缓存 + 路径重写)?
   —— 1.1 的 CF 代理必须是**服务**;只能放静态的话,CF 就只能退回"key 编进客户端"。
3. 流量/带宽上限:1.2/1.3/2 里的清单都是 KB 级,不用管;JRE 包是几十 MB 级,要单独算。

## 6. 客户端侧怎么验(我会跑)

* 三个端点各自的**超时 + 断网**用例:拿不到数据时**不阻塞启动**,页面如实显示"没有"。
* CF 代理:正常搜索出结果;**故意让代理 500** → 客户端退回第三方镜像 → 再切断镜像 → **如实报失败**,
  并且**没有任何一条结果被标成 curseforge**。
* 用 dump/抓包证明**客户端发出的任何请求里都不含 key**(`x-api-key` 只应出现在服务端到 CF 的那一跳)。
* 自更新:校验 sha256 后再装;sha256 不匹配 → 拒绝安装并如实报错。
* 中文名表(2.2):正常更新(sha256/条数/version 三条全过)→ 真的换上;**故意改坏 sha256** → 拒绝替换、
  **缓存原样不动**、继续用随包那份;断网/503 → 不阻塞启动,按"没有这份数据"走(界面只是没有中文名)。
  这条已经用**假 transport 喂真文本**在单测里跑过(`src/services/modnames/tests/modnames_test.c`,164 项断言,
  含上面三个场景),**不需要联网**。
