# 13 · 窗口行为(三键语义 / 托盘 / 任务状态恢复)

本文说的是**用户对 C 版窗口三键给的四条规则**,以及它们怎么落地、怎么验。

> 用户原话:「关闭就是关闭,最大化申请悬于其他应用窗口,缩成小窗口,最小化就退出但不杀进程」

**这是新增设计,不是移植。** Python 版 `src/app/main_window.py` 的窗口部分没有这套语义:
它最小化就是最小化到任务栏、关闭即退出、没有置顶、没有小窗口、没有托盘。
所以本文描述的每一条都是按用户口述的规则新写的,`main_window.cpp` 里对应代码块也写明了这一点。

改动清单:

| 文件 | 改动 |
|---|---|
| `src/ui/main_window.h` | 新增 `WindowMode`、四条行为的公开接口、`TaskRecord`、自检脚本入口 |
| `src/ui/main_window.cpp` | 三键重新接线;窗口行为实现;任务状态落盘/恢复;`SXCL_UI_WINCHECK` 自检通路 |
| `src/ui/tray.h` / `src/ui/tray.cpp` | **新增**:任务栏托盘图标(隐藏后的恢复入口) |

## 1. 四条规则 ↔ 四个动作

| 用户说法 | 动作 | 实现 | 客观判据 |
|---|---|---|---|
| 关闭就是关闭 | **真关闭**:退出、释放资源 | `requestClose()` → `closeEvent` → `finishAndQuit()` | 进程消失(pid 查不到) |
| 最大化申请悬于其他应用窗口 | **最大化 + 置顶**;还原即**取消置顶** | `toggleMaximize()` → `showMaximized()` + `SetWindowPos(HWND_TOPMOST)`,还原走 `HWND_NOTOPMOST` | `GetWindowLong(GWL_EXSTYLE) & WS_EX_TOPMOST` 最大化后 = 1、还原后 = 0 |
| 缩成小窗口 | **420x168 的小窗口**,只留标题栏 + 当前任务/进度 + 恢复键;再点一次恢复**原尺寸与位置** | `setMiniMode(true/false)`,`m_normalGeometry` 记住原矩形 | `GetWindowRect` 前后数值;恢复后逐值等于原 rect |
| 最小化就退出但不杀进程 | **隐藏窗口**(不是最小化到任务栏),进程与后台 worker 照跑 | `hideToTray()`(托盘在时);托盘双击/菜单恢复 | `IsWindowVisible(hwnd) = 0` **且** pid 存活 **且** 后台任务进度继续增长 |

四条的**入口**都一样:标题栏那三个键。需要说明的是"小窗口"这一条 ——
Windows 标题栏只有三个键,而用户数了四条规则。**没有**为了多一条规则去动标题栏
(那会破坏已经对齐到 0.00% 的三键视觉),而是让小窗口有自己的入口:

* 托盘右键菜单「缩成小窗口 / 恢复原尺寸」(主打入口,零视觉代价);
* 小窗口面板里的「恢复原尺寸」按钮(用户明确要求"至少保留"的那个键);
* `MainWindow::toggleMiniMode()`(`Q_INVOKABLE`,给自检与后续页面接线用)。

## 2. 状态模型:形态 × 可见性

```
WindowMode(Normal | Maximized | Mini)   ← 形态,三选一
        ×
m_hiddenToTray(bool)                    ← 可见性,与形态**正交**
```

正交是关键:隐藏的窗口仍然可以是 Normal/Maximized/Mini 中的任何一种,
回来时照原样恢复(最大化状态下退的界面,回来还是最大化 + 置顶)。
「隐藏」因此**不进** `WindowMode` 枚举。

**窗口状态只有一个写入口**:标题栏三键、标题栏双击(`FluentTitleBar::maximizeRequested`)、
托盘菜单、`SXCL_UI_WINCHECK` 自检脚本,走的都是 `main_window.cpp` 里同一组方法。
否则"谁把窗口藏了 / 谁又把它显示出来"会变成三处互相覆盖,这种 bug 在窗口行为里最难查。

## 3. 关闭 = 真关闭

    requestClose()           标题栏关闭键 / 自检 quit
      └ close()  →  closeEvent
                     ├ 有任务在跑 且 ui.close_mode=ask → 弹窗问一句(默认不问)
                     └ accept() → finishAndQuit()
    finishAndQuit()          托盘「退出」也走它(与关闭键同一个出口)
      1. persistTaskState(true)   **先把任务状态落盘**
      2. stopBackgroundWork()     显式给还在跑的 worker 线程发收工请求
      3. 托盘图标先收掉(否则任务栏留幽灵图标)
      4. QCoreApplication::quit() 退出事件循环

**"默认直接退出"** —— 用户明确要求。只有设置里写了 `ui.close_mode=ask` 才会弹窗;
`SXCL_UI_CLOSE_MODE` 是取证通路(钉条件,不改用户配置)。

落盘在**停 worker 之前**:顺序反过来就晚了 —— worker 停下会把没下完的产物清掉。

`stopBackgroundWork()` **不发 wait()**:主线程等下载线程会把"关闭"变成一个卡住的关闭。
真正的 join 由 worker 自己的析构完成(`install_worker.cpp:104-113`、`launch_worker.cpp:45-53`:
置取消标志 → `quit()` → `wait()`),页面随窗口析构时执行 —— 也就是说进程不会带着半死的线程退出。

## 4. 最大化 + 置顶

    toggleMaximize()
      ├ 小窗口形态?        先 setMiniMode(false) 退出(否则没有"最大化"的基准矩形)
      └ 已最大化? showNormal() + HWND_NOTOPMOST   否则 showMaximized() + HWND_TOPMOST

用 `SetWindowPos(HWND_TOPMOST / HWND_NOTOPMOST, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)`,
不用 Qt 的 `Qt::WindowStaysOnTopHint`:`setWindowFlag` 会**重建原生窗口**,
那会把最大化状态的矩形和 DWM 状态一起丢掉;而且判据也要直接读 `WS_EX_TOPMOST` 才硬。

**置顶与最大化必须同生同灭**,所以除了两条入口,`changeEvent(WindowStateChange)` 里还有一道同步:
用户从任何入口进出最大化(标题栏双击、系统快捷键),`WS_EX_TOPMOST` 都跟着走。
只接按钮点击那条路一定会漏。

自证:`MainWindow::isTopMost()` 直接 `GetWindowLongPtrW(hwnd, GWL_EXSTYLE) & WS_EX_TOPMOST`,
不读 Qt 的 hint 标志 —— 读数与 PowerShell 侧独立取的是同一个量。

## 5. 缩成小窗口

**"小窗口"的定义**(尺寸是定的,不是随手写一个):

| 项 | 值 | 理由 |
|---|---|---|
| 宽 | 420 | 放得下标题栏三键(46x32 各一)+ 一行任务文字,再窄标题会开始省略 |
| 高 | 168 | 标题栏 48 + 面板 120(任务一行 + 进度条 + 恢复键 + 边距) |
| 保留 | 真标题栏(三键照旧可用) | 用户要求"至少保留标题栏" |
| 保留 | 「当前任务:<标题> · <进度>%」一行 + 进度条 | 用户要求"至少保留当前任务/进度" |
| 保留 | 「恢复原尺寸」按钮 | 用户要求"至少保留恢复按钮" |
| 藏起来 | 导航面板 + 内容栈 | 小窗口不是"缩小版主界面",是**只报进度**的形态 |

进入/退出的几何规则:

* 进小窗口前用 `QWidget::normalGeometry()`(最大化态)或 `geometry()`(普通态)记下原矩形;
  不先 `showNormal()` 再读 `geometry()` —— 那要等窗口系统把还原做完,读早了拿到的还是最大化尺寸。
* 主窗口最小尺寸是 900x600,所以进小窗口时**临时放宽**到 420x168,退出时恢复 900x600。
* 位置上沿用原左上角(看起来是"原地缩小"),但夹回屏幕可用区,免得缩完跑到屏幕外。
* 退出小窗口:`setGeometry(m_normalGeometry)` —— 原尺寸**与**位置,逐值相等。
* 小窗口形态下标题栏铺满整宽(导航藏了,x<46 那一段没人)。**只有几何变了**:
  三键的尺寸、图标几何、悬停色仍是 libqf 原样,`main_window.cpp` 里那三个 `Shell*Button` 类一个字没改。

## 6. 最小化 = 隐藏窗口(进程照跑)

    hideToTray()
      └ 有托盘? hide()      没有托盘? 什么都不做,只记一行日志

**为什么没有托盘就不隐藏**:藏了之后用户没有任何入口把窗口叫回来,
进程会变成不可见的后台残留(任务管理器里才看得到)。宁可不隐藏,也不能让窗口失踪。
同理,`QCoreApplication::setQuitOnLastWindowClosed(false)` **只在真的有托盘时**才打开 ——
这条规则是"最小化 ≠ 退出"的前提,没有托盘还打开它,窗口一关进程就留在后台。

托盘(`src/ui/tray.cpp`,`QSystemTrayIcon`):

| 元素 | 行为 |
|---|---|
| 图标 | 优先用图标注册表里已加载的 PCL 矢量图(按主题色着色);读不到就画一个主题色圆角块 + 白字 S。**绝不返回空图标** —— 空图标在 Windows 上是"看不见但点得到"的一块 |
| 左键单击 / 双击 | 显示主窗口(`show()` + `raise()` + `activateWindow()`;最大化形态补回置顶) |
| 右键菜单「当前任务:…」 | 只读信息行:界面收走之后,这是"任务还在不在跑"的唯一可见处 |
| 右键菜单「显示主窗口」 | 同上 |
| 右键菜单「缩成小窗口 / 恢复原尺寸」 | 小窗口的入口(菜单文案跟着形态走) |
| 右键菜单「退出」 | 走 `finishAndQuit()`:先结束 worker + 落盘,再退出 |

**"最小化"是对动作说的,不是对按钮说的**:窗口被系统最小化(任务栏按钮、Win+Down)时,
`changeEvent` 里也会转到 `hideToTray()` —— 用户给的规则不该只在点那个按钮时成立。

## 7. 任务状态落盘 / 下次启动恢复

状态文件:`<设置文件同目录>/pending_tasks.json`(设置路径见 `workers/ui_paths.cpp`;
`SXCL_UI_SETTINGS` 一钉,取证就落在临时目录里,不污染用户真实配置)。

```json
{
  "schema": 1,
  "app": "Silent X Craft Launcher",
  "interrupted": true,
  "closedAt": "2026-09-21T15:20:31",
  "tasks": [
    { "id": "download_progress_1.21.11", "kind": "download", "title": "下载 1.21.11",
      "status": "准备中", "versionId": "1.21.11", "versionName": "1.21.11",
      "loaderType": "none", "loaderVersion": "" }
  ]
}
```

* 写:`persistTaskState()` —— 窗口隐藏时与关闭时各写一次。只写**那一刻实测还在跑**的任务
  (判据见 §8),跑完的不写;一个都不在跑就把文件删掉(免得下次开机去"恢复"一个早就做完的任务)。
* 读:`loadTaskState()` —— 启动时读回来,登记进任务表;**默认自动恢复**。
* 恢复走**产品路径**:重新打开下载进度页,安装引擎自己按 SHA-1 复核磁盘上已有的文件
  (已完整的跳过、没下完的续传)。这里**没有**另写一条"续传"捷径 —— 恢复就是重排同一个任务。
* 文件**消费一次就删**:恢复过一次就不再重复恢复。
* 无人值守(offscreen / 无显示平台)时**不自动起网络任务**:没人能看见、也没人能取消它。
  这种情况下只登记不启动,`SXCL_UI_RESUME_TASKS=0/1` 可以钉死这个行为。

## 8. "任务还在跑"的判据(不靠猜)

    int runningThreadsUnder(QWidget *page);   // 页面子树里 isRunning() 的 QThread 个数

`install_worker.cpp:118` 与 `launch_worker.cpp:58` 都是以 worker 自己为父建 QThread,
而 worker 挂在会话页上。于是"页面子树里正在运行的 QThread"就是正在跑的任务:

* **不** include `workers/*.h`:不依赖 worker 的类型与成员,页面改实现不影响这里;
* **不**拿"界面在不在"当判据:窗口藏起来之后界面本来就不可见,而那恰恰是要证明任务还在跑的场景;
* 进度取页面**自己**那根 `QProgressBar` 的值(`main_window.cpp:198` 的 `pageProgressBar`),
  不另立一份计数 —— 两个数字对不上比没有数字更糟。

## 9. 已知限制

1. **跨重启不自动恢复窗口尺寸。** 小窗口记住的原 geometry 只在**本次会话内**有效,
   下次启动仍从 1100x750 开始。这是有意的:上次拖成小窗口之后,下次打开还是小窗口会很怪。
   (任务状态跨重启,窗口几何不跨重启 —— 两件事分开。)
2. **没有托盘就没有"最小化=隐藏"。** 见 §6:这种情况下最小化键什么都不做,只记一行日志。
   代价是"最小化不生效",换来的是"窗口不会失踪"。
3. **置顶是"申请",不是"保证"。** `WS_EX_TOPMOST` 只保证在我们这个窗口层级里排最上;
   别的程序如果也申请了置顶、或者系统有独占前台的需求(全屏游戏、UAC 提示),
   仍然可能盖住我们 —— 这跟"申请到了"不矛盾,读数看的是 `WS_EX_TOPMOST` 这一位。
4. **退出时 worker 的收尾长度由核心库决定。** 取消是"在当前文件边界上停下"
   (install.h 的取消语义),所以退出最多要等当前这个文件下完。
   界面这边不做无限等待,但也不 detach 线程(那会拿已析构的 this 回调,是崩溃不是偶发)。
5. **离线运行时自动恢复会失败**,并如实报错(核心库给的人话原因),不会假装在下载。
6. **小窗口形态下标题栏铺满整宽**(x 从 46 变成 0)。这是小窗口独有的几何,
   正常/最大化形态与参考图的 1:1 对齐不受影响。

## 10. 复现命令

```powershell
# 客观读数验收(独立于程序自述,见 tools/window_behavior_check.ps1 的文件头)
pwsh -File tools/window_behavior_check.ps1 -Exe "build-ui\src\ui\Release\sxcl-ui.exe"
```

自检通路本身(`SXCL_UI_WINCHECK`)支持的命令:

| 命令 | 作用 |
|---|---|
| `probe` | 只打一行客观读数(不改状态) |
| `max` / `normal` | 进/出 最大化 + 置顶 |
| `togglemax` | 同标题栏最大化键(点一次进、再点出) |
| `mini` / `unmini` | 进/出 小窗口 |
| `min` / `show` | 隐藏到托盘 / 显示主窗口 |
| `download:<版本id>` | 起一个真实下载/安装任务(走产品路径) |
| `wait:<毫秒>` | 本步多等一会儿 |
| `quit` | 走产品路径关闭(`requestClose`) |

命令之间用 `;` 分隔,默认每步间隔 900ms。它**只驱动产品路径**,不直接改窗口状态 ——
所以"自检过了"和"用户点出来"是同一件事。
