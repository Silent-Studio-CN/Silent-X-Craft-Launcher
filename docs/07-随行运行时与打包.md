# 07 · 随行运行时与打包

> 用户要求:**exe 必须自带 Qt 运行时,DLL 与 exe 同目录,不依赖 PATH。**
> 用户原话:"新增没问题,问题是找不到要注意目录摆放" —— 加新模块从来不是问题,
> 问题是**摆放**:该在的文件不在 exe 同目录,运行时就是"找不到 DLL/插件"。

## 1. 部署怎么做(CMake,构建时自动)

| 函数 | 谁用 | 铺什么 |
|---|---|---|
| `sxcl_deploy_qt(target)` | 测试目标(`sxcl_net_qt_test` `sxcl_ui_smoke_test` …) | 目标真实依赖的 DLL + `platforms/` + `tls/` |
| `sxcl_deploy_qt_full(target)` | `sxcl-ui`、`sxcl-dl` | 先 `windeployqt`(插件全家桶),再补离屏插件,最后跑摆放自检 |

**DLL 清单不再手写**:首选 CMake 3.21+ 的 `$<TARGET_RUNTIME_DLLS:target>` —— 它按目标的
链接接口算出"运行时真正要 import 的 DLL"。于是:

- 谁加了新的 Qt 模块(Widgets / Multimedia / Charts …),**不用改 CMakeLists**,它的 DLL 自动跟着铺;
- 只有 CMake < 3.21 才走**兜底**分支(手写 Core/Gui/Network/Svg)。那张表**不会自动跟进**:
  实测它漏了 `Qt6Widgets.dll` —— 用 QWidget 的测试目标一直靠"测试环境把 Qt 的 bin 塞进 PATH"
  才跑起来,干净机器上就会缺。

插件是**另一回事**,固定三样,少一样就是事故:

| 插件 | 为什么必须有 |
|---|---|
| `platforms/qwindows.dll` | 起窗的最低要求,没有它连窗口都建不出来 |
| `platforms/qoffscreen.dll` | **windeployqt 不铺**(实测 `windeployqt --list relative` 里没有它);离屏跑测试/截图要用,缺了直接 `Could not find the Qt platform plugin` |
| `tls/*.dll` | HTTPS 的后端(`qschannelbackend` / `qopensslbackend` …);缺了就是 `qt.network.ssl: No functional TLS backend was found` —— **下载全废**(踩过) |

TLS 插件按配置分拣:只拷与当前配置匹配的那份(`qschannelbackend.dll` vs `...d.dll`),
不把 debug 插件混进 Release 目录(打包时要剔除杂物,见 §4)。

`dxcompiler.dll + dxil.dll`(约 15MB)是 Qt6 RHI 的 D3D 着色器编译器,纯 Widgets 用不到,
打包时若确认无 RHI/Quick 依赖可考虑剔除(需实测启动无缺 DLL 报错)。

## 2. 摆放自检:`tools/check_qt_deploy.ps1`(构建后必跑)

只做一件事:对 exe(或 exe 所在目录里的**每个** exe)断言"运行时真正需要的文件就在
exe 同目录/子目录"。**缺任何一个 -> 脚本非零退出 -> 构建失败**,并逐条打印
"缺哪个文件、应该在哪个目录、为什么"。

判定依据三路互补(所以 windeployqt 不在场时自检依然有效,不会退化成"什么都不查"):

1. **权威清单**:`windeployqt --list relative <exe>`(与部署时**同一套参数**,见
   `SXCL_WINDEPLOYQT_FLAGS`;参数不一致会去要求本来就不打算铺的文件);
2. **PE 导入表**:纯 PowerShell 解析 exe(以及同目录已铺的每个 `Qt6*.dll`)的导入表,
   `Qt6*.dll` 必须与 exe 同目录 —— 不依赖任何外部工具;
3. **插件目录规则**:import 了 `Qt6Gui` 就必须有 `platforms/qwindows.dll` +
   `platforms/qoffscreen.dll` + `styles/` + `imageformats/`;import 了 `Qt6Network`
   就必须有 `tls/` 下的后端插件;import 了 `Qt6Multimedia` 就必须有 `multimedia/`
   后端插件(ffmpeg/windowsmedia —— 我们现在不链它,规则是给"哪天开媒体模块"准备的)。

> ⚠️ **自检脚本踩过的坑(别改回去)**:`windeployqt --list relative` **不是"只看不写"** ——
> 它会真的把文件铺出去。不 dry-run 的话,自检会先把"缺的文件"悄悄补好,再断言"都在位",
> 于是**永远测不出问题**(反向验证时抓到的:移走 `tls/qschannelbackend.dll`,自检却次次通过,
> 文件还被铺了回来)。所以脚本固定用 `--dry-run --list relative`;老版本 windeployqt 没有
> `--dry-run` 时退回 `--dir <临时目录>`,让副作用落在临时目录里。另外断言统一放在
> **所有 windeployqt 调用之后**(两阶段:先收集"该有什么",再断言存在性)。

接法(默认开):`sxcl_deploy_qt_full()` 的最后一步就是它,所以 **`sxcl-ui`(build-ui)与
`sxcl-dl`(build)** 一构建就检。跳过只有两个口子:

```powershell
$env:SXCL_SKIP_DEPLOY_CHECK = '1'      # 构建时跳过(极特殊情况,默认必须跑)
cmake -S . -B build -DSXCL_DEPLOY_CHECK=OFF   # 整体关掉这一步
```

手工单独跑(参数 = exe 目录或 exe 路径;退出码 0 通过 / 1 有缺失 / 2 用法或环境错误):

```powershell
pwsh -NoProfile -File tools/check_qt_deploy.ps1 build-ui/src/ui/Release
pwsh -NoProfile -File tools/check_qt_deploy.ps1 build/Release/sxcl-dl.exe
pwsh -NoProfile -File tools/check_qt_deploy.ps1 build/Release -ShowImports   # 只打印导入表(取证)
```

## 3. 清空 PATH 复验(每次改完部署相关都要跑)

```powershell
$env:PATH = 'C:\Windows\System32;C:\Windows'      # 清空 Qt 路径
$env:SXCL_UI_SHOT='<仓库>\build\ref\c_dllcheck.png'
& '<构建目录>\src\ui\Release\sxcl-ui.exe'
# 判据:PNG 生成成功 = 运行时不依赖 PATH
```

## 4. 打包时必须剔除的构建产物(现在和 exe 混在同一目录)

- `sxcl_ui_core.lib`(静态库中间产物)
- `sxcl_ui_smoke_test.exe` 等测试程序
- debug 版插件(`*d.dll`)—— 部署函数已按配置分拣,正常不会出现

## 5. libqf(PyQf)的多媒体模块:不编、不链、不部署

`D:\SilentStudio\PyQf to C` 那棵树的两个默认值是 `ON`:

| 它那边的 option | 默认 | 会带出什么 |
|---|---|---|
| `PYQFTO_MULTIMEDIA` | ON | `fluent` 静态库追加 `fluent_multimedia.cpp`,并 `find_package(Qt6 REQUIRED COMPONENTS Multimedia MultimediaWidgets)`;对 `fluent` 是 PRIVATE |
| `PYQFTO_BUILD_DEMO` | ON | `fluent_demo` 可执行目标,显式链 `Qt6::Multimedia Qt6::MultimediaWidgets`(静态库的 PRIVATE 依赖不传播,所以它自己再链一遍) |

也就是说:**一旦构建/部署/运行 `fluent_demo`,`Qt6Multimedia.dll` 与 `Qt6MultimediaWidgets.dll`
必须与 `fluent_demo.exe` 同目录,而且 `multimedia/` 后端插件(FFmpeg 编解码栈)也要一起铺** ——
正是"目录摆放"最容易漏的那种。

启动器一个都用不到,所以在进它的 CMakeLists 之前就关掉(根 `CMakeLists.txt` 的 `SXCL_BUILD_UI` 分支):

```cmake
set(PYQFTO_MULTIMEDIA OFF)
set(PYQFTO_BUILD_DEMO OFF)
set(PYQFTO_BUILD_TESTS OFF)
add_subdirectory(src/ui)          # PyQf 由 src/ui 引入
if(TARGET fluent_demo)            # 兜底:谁把 demo 放回来,这里当场配置失败
  message(FATAL_ERROR "…会链 Qt6::Multimedia,把 ffmpeg 后端与 multimedia/ 插件拖进部署")
endif()
```

- 理由是**体积 + 再分发许可**(FFmpeg 编解码栈)与"多一套要摆的插件目录",不是功能缺失;
- `CMP0077` 下普通变量优先于 `option()`,所以 `set` 就够:**不改 PyQf 仓库、不用清缓存**;
- 代价:哪天真要用媒体页,必须同时打开这两个 option,并给 demo 的部署目录单独跑一次
  `check_qt_deploy.ps1`(`Qt6Multimedia` 在导入表里,它的 `multimedia/` 插件规则目前不在自检里 ——
  见 §6 未做)。

## 6. 各平台打包(阶段 8,待做)

| 平台 | 随行方式 | 注意 |
|---|---|---|
| Windows | Inno Setup 安装包;或便携 zip | 必须把 §1 的 DLL + `platforms/` 一起打进去;剔除 §4 |
| Linux | AppImage | 需带 Qt 的 `platforms/libqxcb.so` 与 xcb 相关依赖;`linuxdeployqt` 或手工铺 |
| macOS | `.app` bundle + DMG | Qt 框架放进 `Contents/Frameworks`,`macdeployqt` 处理 rpath |
| Android | APK | Qt for Android 把运行时装进 APK 的 `lib/`;无"同目录 DLL"问题,但要有 `--android-platform` 等配置 |

## 7. 控制台窗口(成品观感)

实测 PE 子系统 = **3(CONSOLE)** -> 启动器旁边会弹一个黑窗口。

- 开发/验收阶段**保留**控制台(工具链与各页自检都靠 stderr 诊断);
- **打包时**加 `-DSXCL_UI_WINDOWS_GUI=ON` -> PE 子系统 = 2(GUI,无控制台)。

## 8. 还没做

- 自检只覆盖 Windows(x64):Linux/macOS 的插件目录名不同(`libqxcb.so`/`platforms/libqcocoa.dylib`),
  脚本不适用;等阶段 8 的平台打包时再各写一份。
- `CheckQtDeploy` 目前挂在 `sxcl-ui` 与 `sxcl-dl`(全量部署)上;轻量部署的测试目标依赖
  测试环境往 PATH 里塞 Qt bin,没逐个做摆放断言。
- 未校验"多余文件"(例如 `dxcompiler.dll` 是否该剔除):自检只报"缺",不报"多"。
