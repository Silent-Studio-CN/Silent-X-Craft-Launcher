# 07 · 随行运行时与打包

> 用户要求:**exe 必须自带 Qt 运行时,DLL 与 exe 同目录,不依赖 PATH。**

## 1. 现状(已实测:清空 PATH 只留 System32 仍能起窗并截图)

构建时由 CMake 的部署函数自动完成(每个构建目录都生效):

| 项 | 内容 |
|---|---|
| Qt DLL(7) | `Qt6Core.dll` `Qt6Gui.dll` `Qt6Widgets.dll` `Qt6Network.dll` `Qt6Svg.dll` + `dxcompiler.dll`(13.6MB) + `dxil.dll`(1.4MB) |
| 插件 | `platforms/`(**qwindows.dll** + qoffscreen.dll)、`styles/qmodernwindowsstyle.dll`、`tls/`(qschannelbackend + qcertonlybackend)、`imageformats/`(qgif/qico/qjpeg/qsvg)、`iconengines/qsvgicon.dll`、`generic/qtuiotouchplugin.dll`、`networkinformation/qnetworklistmanager.dll` |

- `qoffscreen.dll` 是**我们额外铺的**:离屏跑冒烟测试需要它,windeployqt 只铺 qwindows。
- `dxcompiler.dll + dxil.dll` 共 **15MB**,是 Qt6 RHI 的 D3D 着色器编译器;纯 Widgets 应用用不到。
  打包时若确认无 RHI/Quick 依赖,可考虑剔除(需实测启动无缺 DLL 报错)。

## 2. 打包时必须剔除的构建产物(现在和 exe 混在同一目录)

- `sxcl_ui_core.lib`(静态库中间产物)
- `sxcl_ui_smoke_test.exe`(测试程序)

## 3. 控制台窗口(成品观感)

实测 PE 子系统 = **3(CONSOLE)** → 启动器旁边会弹一个黑窗口。
- 开发/验收阶段**保留**控制台(工具链与各页自检都靠 stderr 诊断);
- **打包时**加 `-DSXCL_UI_WINDOWS_GUI=ON` → PE 子系统 = 2(GUI,无控制台)。

## 4. 各平台打包(阶段 8,待做)

| 平台 | 随行方式 | 注意 |
|---|---|---|
| Windows | Inno Setup 安装包;或便携 zip | 必须把 §1 的 DLL + `platforms/` 一起打进去;剔除 §2 |
| Linux | AppImage | 需带 Qt 的 `platforms/libqxcb.so` 与 xcb 相关依赖;`linuxdeployqt` 或手工铺 |
| macOS | `.app` bundle + DMG | Qt 框架放进 `Contents/Frameworks`,`macdeployqt` 处理 rpath |
| Android | APK | Qt for Android 把运行时装进 APK 的 `lib/`;无"同目录 DLL"问题,但要有 `--android-platform` 等配置 |

## 5. 复验命令(每次改完部署相关都要跑)

```powershell
$env:PATH = 'C:\Windows\System32;C:\Windows'      # 清空 Qt 路径
$env:SXCL_UI_SHOT='<仓库>\build\ref\c_dllcheck.png'
& '<构建目录>\src\ui\Release\sxcl-ui.exe'
# 判据:PNG 生成成功 = 运行时不依赖 PATH
```
