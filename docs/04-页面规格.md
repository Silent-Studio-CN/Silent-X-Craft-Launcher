**页面骨架（`src/app/common/base_page.py`，全部页面共用）**：`BasePage(ScrollArea)` → `self.view`（透明 QWidget，`setWidgetResizable(True)`，横向滚动条永久关闭）

**状态与禁用**

- 空态：`versions/` 无任何版本目录 → 显示"暂无已安装的版本\n前往「版本」页下载"，版本列表容器 `setVisible(False)`。
- 非空：空态标签隐藏，列表可见，卡片数 = 已安装版本数；每张卡固定高 56（高度是**常量**，可直接断言像素高度）。
- 加载中：**没有**加载中态（纯本地扫描，同步）。
- 错误态：无页面级错误；打开目录失败走 InfoBar。
- 按钮禁用：**没有任何按钮会进入禁用态**（"启动"只在 Java 未设置时给提示，不置灰）。

**主题与图标**：图标 = `FluentIcon.HOME`（导航）、`FluentIcon.GLOBE`（联机入口，28px 位图）；草方块为代码自绘。

**状态与文案**

- 加载中：加载区可见 + `正在加载版本清单…`；`刷新` 禁用；模型清空（列表 0 行）。
- 成功：状态行 `共 {N} 个版本，已安装 {M} 个` + 加载器汇总；过滤后 `共 {N} 个版本，已安装 {M} 个 | 当前显示 {K} 个` + 汇总。
  加载器汇总 = `｜加载器：` + `"、".join(f"{名字} {个数}")`（按名字排序）+ 有任一加载器个数>1 时追加 `（同一原版装了多个加载器）`；无加载器时为空串。
- 空结果：`没有匹配的版本`（仍是状态行，列表 0 行）。
- 错误：状态行 `加载失败` + InfoBar.error `加载失败` / `无法获取版本清单：{error}`（5000ms）；`刷新` 恢复可用。
- 禁用条件：仅"刷新"在请求进行中禁用。行内两枚按钮**无禁用态**（仅在悬停时绘制）。

**主题与图标**：草方块/加载器/出错状态图来自 `src/app/icons.py`（当前实现走 `assets/icons/blocks/*.png`，找不到时 QPainter 自绘，按屏幕 DPR 生成）。
令牌：`hover`、`hover_strong`、`text`、`text_tertiary`、`success`、`danger`、`accent`（按钮描边）、加载器色 `LOADER_COLORS`（硬编码十六进制，非令牌）。

## 6. 与 C 版已定结构的冲突清单

> C 版已定结构（任务书口径）：**主页 / 下载 / 任务 / 联机 / 更多 五项主导航 + 设置沉底**。
> 已核对：C 版仓库的 `docs/`、`README.md` 里**没有**这份导航结构的文字记录（`docs/02` 无导航设计），故以下以任务书口径为准。

1. **导航项集合与顺序不同。** Python 实际：`主页 / 版本 / 任务 / 按键映射 / 联机` + 沉底 `设置`。差异：第 2 项是"版本"（非"下载"）；第 4 项是"按键映射"（C 版该位是"联机"）；**Python 没有"更多"页**。
   > 与 C 版已定结构冲突：C 版是 主页/下载/任务/联机/更多 + 设置沉底，Python 是 主页/版本/任务/按键映射/联机 + 设置沉底。判断：**导航顺序以 Python 实际实现记录**（本节即事实），但 C 版已定结构是产品决策，二者必须由产品确认后再定 UI 测试基线；本规格的断言全部以 Python 事实为准。
2. **"下载"不是顶层页。** Python 里下载是**从版本列表点一行后压栈的临时页**（`DownloadConfigPage` + `DownloadProgressPage`），退出必须点"←  返回版本列表"（`go_back_to_versions()`，结束会话）。若 C 版把"下载"做成导航项，就没有这份"临时页 + 返回版本列表"的会话语义。
   > 与 C 版已定结构冲突：C 版把下载列为导航项，Python 是临时页。判断：C 版需明确"点下载导航项时右栏显示什么"以及"下载完成后回到哪"——Python 版无法提供对照。
3. **没有"更多"页，设置也不是二级导航。** Python 的设置是常驻页面（导航沉底项），直接平铺 5 个 `SettingCardGroup`；PCL 的"更多/其他"（`icon_a209b3cb.svg`）在 Python 版**不存在对应页面**。
   > 与 C 版已定结构冲突：C 版有"更多"导航项，Python 无。判断：C 版需要自行设计"更多"页内容（Python 版无可复刻物）。
4. **断言样例里的左右分栏与左栏多项在 Python 版不存在。** 例："左栏列表项数 >= 5 且第一项文本 == '原版游戏'"、"点第 3 项后右栏出现文本'整合包'"——这是 PCL `PageDownloadLeft` 的分类结构（原版游戏/整合包/Mod/数据包/资源包/光影包，对应 index.tsv 的 `pathversion/modpack/mod/datapack/resourcepack/shader`）。Python 版本页是"搜索框 + 分类下拉（全部/正式版/快照/旧版）+ 刷新 + 单列虚拟列表"。
   > 与 C 版已定结构冲突：C 版要左栏分类列表，Python 是单列列表 + 下拉。判断：这两条断言**只能作为 C 版自定基线**，不能声称"复刻 Python"；若要复刻 Python，用本规格 §2.2 的 16 条。
5. **导航名与页标题不一致的既有事实。** 导航项"版本" ↔ 页标题"游戏版本"。C 版若导航叫"下载"，页标题是叫"下载"还是"游戏版本"需明确。
   > 与 C 版已定结构冲突：C 版导航文案"下载"，Python 导航"版本"+页标题"游戏版本"。判断：建议 C 版页标题与导航项同名，但这是产品选择。
6. **主页语义不同。** Python 的主页 = "已安装版本列表 + 快速启动 + 游戏目录卡 + 联机入口"；PCL 的主页/启动页是"选版本 + 启动按钮 + 账户"。
   > 与 C 版已定结构冲突：C 版"主页"若按 PCL 启动页做，与 Python 主页结构不同。判断：以 C 版产品决策为准，但 Python 主页的 13 条断言不能直接套用。
7. **设置页分组顺序与项集含 Python 特有项。** Python 有"版本隔离 / 下载设置（并发、限速、SHA1）/ 多线程下载引擎-测试 / 版本列表刷新频率"等 PCL 没有的项，同时缺 PCL 的"启动设置 / 个性化 / 帮助"等组。
   > 与 C 版已定结构冲突：C 版若照 PCL 的 `PageSetup*`（启动/个性化/联机/其他）分组，与 Python 的 5 组（通用/游戏/下载/高级/关于）对应不上。判断：以 Python 的 5 组为复刻基准，PCL 分组作为可选。
8. **按键映射页在 C 版结构里没有位置。** Python 把它放在主导航第 4 项；C 版五项里没有它（可能归到"更多"）。
   > 与 C 版已定结构冲突：C 版导航无"按键映射"。判断：C 版需决定它去"更多"还是另开入口；页面本体（§2.4）可直接复用，仅导航位置待定。

**源码内部不一致（Python 版自身，复刻时不要照抄）**

- 下载进度页 UI 阶段表与 worker 实际阶段表**不一致**：UI 有"安装完成"、没有"解压 natives"；worker 有"解压 natives"、最后一步叫"整理文件"（`download_progress_page.py:246-262` vs `:555-572`）。→ C 版应以 worker 实际阶段为准并**对齐 UI 列表**。
- 主页版本卡的加载器名按目录名子串判断，`if "forge"` 在 `if "neoforge"` 之前 → **NeoForge 实例显示成 "Forge"**（`home_page.py:220-227`）。
- "启动时自动检查更新"开关存在，但 `MainWindow._check_updates` 是 `pass`；`on_download_source_changed` 也是 `pass`。
- `_register_page` 的 `persistent` 集合是 `{"home","versions","tasks","settings"}`，**漏了 `keymap`/`multiplayer`**（会话页超 24 个时可能被误回收）。
- 重置默认值把下载源设为 **BMCLAPI**，而初始化默认是 **AUTO（智能）**（`settings_page.py:457` vs `launcher_config.py:116`）。
- `styles.py` 明令"页面里不许出现硬编码颜色"，但仍有：主页空态 `#888`、任务页 `#888`/`#999`、Java 卡 `#52c41a/#73d13d/#fa8c16/#ffa940/#ff4d4f/#ff7875/#0078d4/#00bcf2`、两个进度页的指示器 `QColor(0,120,212)/(82,196,26)/(255,77,79)/(200,200,200)`、加载器色表 `LOADER_COLORS`。
- `DownloadProgressPage._apply_theme_styles` 刷新的 `self._divider` 在 `_build_content` 里**从未创建**（分隔线被删了但代码没删）→ C 版不要保留这一行。

## 7. 核心层缺口（按重要性排序）

1. **实例扫描与识别（`sxcl/instance.h`）** —— 扫 `<游戏目录>/versions/*` 产出"实例 id / 对应原版 base / 加载器 [(kind,version)] / 是否可启动 + problem 文案"。阻塞：主页列表、版本页"已安装"与加载器标签、下载配置页的重名与同加载器判定、任务页。C 版现状：`sxcl_loader_installed`（`loader.h:147`）只定义了入参结构，**没有任何扫描实现**；`sxcl_version_list_*` 只管远端清单。
2. **加载器版本列表获取（元数据层）** —— Forge / NeoForge / Fabric / OptiFine 在指定原版下的可用版本 + `最新/推荐/Beta` 标记 + OptiFine 的 `forge` 字段。阻塞：下载配置页的四个 LoaderRow（现在只能靠 UI 层用 Qt 自己发 HTTP，且要复刻 BMCLAPI/官方双源与 fallback）。C 版现状：无（`loader.h` 只吃 `sel->available_versions`）。
