# 15 · 下载源(官方 / BMCLAPI)与"镜像优先"

本文记录"设置里切了下载源,游戏文件还是走官方"这条缺陷在**核心库**里的修法、真实证据与坑。
所有命令都是在 `D:\SilentStudio\prog\Silent-X-Craft-Launcher - C` 下真实跑出来的,输出原文照抄。

相关文件:`include/sxcl/manifest.h`、`src/services/metadata/manifest.c`、`include/sxcl/install.h`、
`src/services/install/install.c`、`tools/sxcl-dl/main.c`、`src/net/transport_qt.cpp`、
`tests/manifest_test.c`、`tests/install_test.c`。

---

## 0. 问题

`download.source = bmclapi` 以前只作用于**清单**(版本列表);游戏文件(版本 JSON / 客户端 jar /
依赖库 / 资源对象 / 加载器安装包)的计划里永远是"官方 `urls[0]`、镜像 `urls[1]`",
镜像只有官方彻底失败才用得上 —— 用户看到的还是"官方慢 / 官方不通"。`download.source` 在核心库里
从来没有人读过。

## 1. 新增的 C API(签名 + 为什么)

```c
/* include/sxcl/manifest.h */
int sxcl_version_plan_prefer_mirror(sxcl_version_plan *plan);
```

- 语义:遍历计划里所有任务,把 `urls[0]` / `urls[1]` **对调**;没有第二候选的任务不动。
  返回被调换的任务数,< 0 = 参数错误(plan 为空)。
- 为什么是"对调"而不是"重排":plan 接管了这些 URL 字符串的生命周期(`plan->owned`),
  换指针就够了,不复制、不释放。
- **只应调用一次**:它只做一次交换、不记状态,调两次就换回"官方在前"。这条写进了头文件注释,
  测试里也顺手钉住了(见 §5)。
- 为什么需要它:资源对象是**后追加**的一批(要先下资源索引才能展开),
  而"镜像优先"必须是每一批各自在下载前定好顺序 —— 见 §2。

## 2. install.c 的接线(为什么一批一次)

`sxcl_install_plan` 增加了 `int prefer_mirror`(放在 `mirror_base` 旁边):

```c
int prefer_mirror;  /* 1 = 镜像优先:镜像排第一、官方作第二候选(不通自动切回);0 = 官方优先 */
```

`mirror_base` 为空且 `prefer_mirror=1` 时用 `SXCL_MIRROR_BMCLAPI_BASE`(默认 bmclapi)。

装配与下载是交错的(阶段表:版本 JSON → 客户端 jar → 依赖库 → 资源索引 → 资源对象),
所以顺序分两处、各定一次,而不是"最后统一换一次":

| 批次 | 位置 | 做法 |
| --- | --- | --- |
| 版本清单(fetch_text) | `stage_manifest` | `prefer_mirror=1` 时先取镜像、失败再取官方 |
| 版本 JSON | `stage_version_json` | 镜像映射出来后按开关放到 `urls[0]` |
| 客户端 jar / 依赖库 / 资源索引 | `stage_version_json` 计划建好后 | `sxcl_version_plan_add_mirror` 补第二路 → `sxcl_version_plan_prefer_mirror`(**只此一次**) |
| 资源对象 | `stage_asset_objects` | 追加时直接对调参数(base=镜像的 `/assets`,第二候选=官方 CDN);**不能**再调一次 prefer_mirror |
| 加载器安装包 | `stage_loader_installer` | 认得出的 URL 才补镜像,认不出就只有官方一条路(不造假 URL) |

`mirror_base` 是"镜像根"(与 `add_mirror` 一个口径,如 `https://bmclapi2.bangbang93.com`),
资源对象在它下面的 `/assets`;调用方已经写成 `.../assets` 时不再拼一层。

## 3. 命令行 `--source`

```
sxcl-dl version <版本号|latest> <游戏目录> [--source bmclapi|mojang|auto] [...]
  └ --source 决定哪条路排第一(默认 bmclapi):bmclapi/auto = 镜像优先、官方作第二候选
    (镜像不通自动切官方);mojang = 官方优先
```

默认 **bmclapi**(与设置页默认一致)。`--verbose` 下每个文件的完成行会打出
**真正成功的候选下标与它的 URL**(`来源 #N <url>`),这样"镜像排第几"是日志里的直接证据。

## 4. 顺带修掉的真机缺陷:Qt 传输不跟 302(BMCLAPI 全是 302)

第一版改完做真机验证时,`来源 #` 几乎全是 **1(官方)** —— 说明镜像那条路每次都被跳过。
用 `SXCL_NET_DEBUG=1` 看原始响应:

```
QT https://bmclapi2.bangbang93.com/mc/game/version_manifest_v2.json (h2=1 range=-1) -> 302
  location: https://14.749333.xyz:443/download/b7c75...?...&name=version_manifest_v2.json
```

BMCLAPI 对**每个文件**都先 302 到预签名 URL 再 200(curl 实测 2 跳)。
`src/net/transport_qt.cpp` 的等待循环"一看到状态码就跳出",拿到的是第一跳的 302,
于是镜像永远算"HTTP 302 失败"、每次都回落官方 —— 镜像排第一等于白排。
修法:301/302/303/307/308 且 Qt 还在跟(reply 未结束)时**继续等**,直到最终状态或超时。

## 5. 实测证据

构建(VS 17 2022 这台机器上没装,只有 VS 18 2026 Insiders,故用了它):

```
cmake -S . -B build-src -G "Visual Studio 18 2026" -A x64 -DSXCL_BUILD_UI=OFF -DSXCL_BUILD_TESTS=ON \
      -DCMAKE_PREFIX_PATH=D:/Qt/6.11.2/msvc2022_64      # 有 Qt 才有下载传输后端
cmake --build build-src --config Release                # exit 0(/W4 /WX 无警告)
ctest --test-dir build-src -C Release                   # 100% tests passed out of 34
```

单元测试:

```
元数据层测试: 通过 73 项, 失败 0 项
  [PASS] 版本清单/rules 过滤/natives/下载计划 全部符合预期
  [下载源(镜像优先)] 通过 12 项, 失败 0 项
install 编排测试: 通过 277 项, 失败 0 项
```

覆盖:(a) 两个候选的任务换序后 `urls[0]`=镜像、`urls[1]`=官方;
(b) 只有一个候选的任务(认不出的域名)原样不动;(c) 没调用 `add_mirror` 时
`prefer_mirror` 返回 0、不制造假 URL;以及"再调一次就换回去"。
install 侧用假 io 断言**每一个**交给下载器的任务第一候选都是镜像、且都留了官方第二候选,
并断言 `prefer_mirror=0` 时没有任何任务把镜像排在第一。

真机端到端(目标目录是 `%TEMP%` 下的临时目录,没碰用户游戏目录):

```
sxcl-dl version 1.0 <临时目录> --skip-assets --verbose

- `index=0` 的 URL 全是 `bmclapi2.bangbang93.com` —— 镜像确实排在第一位。

  引擎自动切到官方并成功 —— "不通自动切"也验证到了。

  **不在**镜像映射表里),它只有一条候选、`prefer_mirror` 没动它 —— 生产环境里
  "没有第二候选的任务不动"的实际样子。

  下载源: 官方优先(mojang),镜像只作第二候选
  来源下标直方图:index=0 count=13   # 13 条全是官方 URL
```

## 6. 没做的

- `sxcl-dl` 没有 `install` 子命令,所以 install.c 那条路没有命令行端到端;
  它的接线由 `tests/install_test.c` 的假 io 断言(12 项)覆盖。
- `get` 子命令的 `--mirror` 仍是"原样第二条 URL"(不做映射),没接 `--source`。
- 清单镜像在 `install.c` 里只在 `prefer_mirror=1` 时才先试镜像;`prefer_mirror=0` 保持老行为。
- 未改 `src/ui/**`、`build/`、`build-ui/`。
