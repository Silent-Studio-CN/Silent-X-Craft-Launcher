## 0 为什么是重写而不是继续修

老界面是三件事的必然结果，改不完：

1. **每页手搓控件**（`settings_page.cpp` 15 万字节，几千行手工布局）→ 间距/对齐一处一个样；
2. **构造期把颜色烤死**（`setStyleSheet(令牌拼出来的串)`）→ 换主题必出事故（浅色半套 / 副标题被挤 / 左边字消失，三次都是我踩的）；
3. **页面直接调网络与文件**（版本页在 GUI 线程上同步请求清单）→ "未响应"（实测两次各 ≈2.3 秒）。

新界面把这三条变成**结构上做不到**。

## 1 视觉语言（"好看"的可执行定义）

- **一个底色，两层浮起**：`bg`（窗口）/ `surface`（卡片，圆角 12）/ `surfaceHover`；**不再用 1px 描边画卡片**，改用极轻的阴影 + 亮度差（现代感的来源）。
- **强调色只出现在"能动手的地方"**：主按钮、选中指示、进度、开关。装饰不用强调色。
- **字号只有五档**：32 / 20 / 15 / 13 / 11（显示 / 页标题 / 小标题 / 正文 / 注释），行高 = 字号 ×1.5。
- **圆角只有三档**：12（卡片）/ 10（按钮、输入）/ 6（小标签）。
- **间距只有四档**：4 / 8 / 16 / 24；页面外边距固定 24。
- **一条 12px 的脏活线**：所有"内部信息"（URL / 路径 / 键名 / 版本号 / 日志）只在折叠区里出现，主界面一个字都不露。

## 2 布局外壳（侧栏问题从此不可能出现）

```
┌──────────────────────────────────────────────────────────┐
│ 标题栏（可拖拽；左上：返回/汉堡；右：最小化 最大化 关闭）    │
├──────┬───────────────┬───────────────────────────────────┤
│ 主导 │ 子栏（可选）   │ 内容区（可滚动，只有**竖向**条）    │
│ 航   │ = 外壳的槽     │                                   │
└──────┴───────────────┴───────────────────────────────────┘
```

- 主导航与子栏都是**外壳的槽**，不是页面里的两列 → "侧1/侧2 中间那道缝""子栏被标题压下去"结构上不可能；
- 主导航 64（图标+文字）/ 折叠 48；子栏 240 / 折叠 48；两者**同一套折叠动画**（220ms OutCubic）；
- 内容区标题属于**外壳**（在内容区顶部，与子栏无关），所以子栏从顶格开始。

## 4 互动与动效（"有互动"的可执行定义）

- **一切过渡 150–220ms**，`OutCubic`；不用弹跳、不用缩放超过 1.02；
- **悬停必有反馈**（背景提亮一档 + 出现该行独有的动作）；
- **键盘可达**：Tab 顺序 = 视觉顺序，Esc 关闭浮层，回车触发主动作；
- **页面切换**：内容区 120ms 淡入 + 8px 上移（不做左右滑，避免"拖动感"）；
- **危险动作**（删除/覆盖）**二次确认**，且默认焦点在"取消"。

## 5 现代感的具体做法（不靠花哨）

- 卡片用"亮度差 + 大圆角 + 内容留白"，**不用描边和分割线**；
- 头像/图标用**自绘 SVG**（现有 `assets/icons` 已够），绝不 emoji；
- 状态用**颜色 + 图标 + 文字**三件套（色盲友好），失败态用 `danger`，警告用 `warning`；
- 数字/时间右对齐等宽，标题左对齐；**一行最多一个强调色块**。

## 9 用户给的取材来源（2026-09-26）与"怎么搬进 Qt"

用户推荐了两个站点（原话：「虽然是 HTML 能用的，不过我还是推荐给你吧」）。它们本身是 CSS/JS 生态，
**不直接拿来用**，但两个站的价值恰好是我们要补的两块：**卡片/按钮的形**与**图标之间的"变形"动效**。

| 来源 | 它给的是什么 | 搬进 Qt 的做法 |
| --- | --- | --- |
| `uiverse.io` | 大量单组件级的 HTML/CSS 片段（卡片、开关、加载、悬停小动效） | 只**取形与交互意图**，落到我们的令牌与组件上：\`HeroCard\` / \`VersionRow\` / \`Toast\` / \`StepBar\`。CSS 的 `box-shadow`/\`gradient\`/\`transform\` 对应到：QSS 的等效属性、\`QGraphicsDropShadowEffect\`、以及 \`QPropertyAnimation\` 驱动的自绘属性；**不引入 WebEngine**（那会把安装包和内存拉垮）。 |
| `morphicons.com` | 图标之间的**形态过渡**（播放↔暂停、汉堡↔关闭、加↔减…） | 这正是 Qt 的强项：把需要的十几个图标做成**路径数据**（\`QPainterPath\`）+ 关键帧插值（\`QVariantAnimation\` 驱动 0→1 的形变系数），一个 \`MorphIcon\` 控件搞定。**不引第三方渲染器**；路径数据可以手写或用现成 SVG 的 d 串解析。 |

**取舍（写在前面，免得后面跑偏）**：

1. **只搬"形与动"，不搬实现**：我们不会为了效果图引入 WebEngine、Lottie、Rive 这类重依赖 ——
   桌面上它们是几十 MB 的代价，而我们最缺的恰恰是"启动快、内存小"。
2. **动效预算**：单个动效 ≤220ms、\`OutCubic\`、不做超过 1.02 倍的缩放（docs/27 §4 已有纪律），
   uiverse 上那些"弹跳/翻转/粒子"只取其中**克制的**部分。
3. **每个动效都要能在 CI 里断言**：要么是几何断言（dump），要么是截图几何/配色比对（sic）。
   看不见的动效 = 没法验收 = 不做。
4. **图标一律自绘 SVG/路径**（用户已两次点名不要 emoji），morphicons 的路径思路正好吻合。

**下一步的具体取材**（M1/M2 期间做，做完把具体组件名记在这一节下面）：

- 主页：卡片悬停抬升的**阴影与亮度**两档差（uiverse 那种"抬起来"的观感）；
- 版本行：悬停齿轮的**淡入 + 微旋**（不弹跳）；
- 启动按钮：按下时的**内阴影**（而不是变色）；
- 图标形变：汉堡↔关闭、启动↔停止、展开↔收起（这三个是用户每天点最多的）。



## 10 V2 修订（2026-09-26 用户看效果图后的口径）

> 用户原话要点：「新 UI 很能打…但还是要改」。逐条记成**施工口径**，实现时照这个来。

### 10.1 能不能用 VB？——不能，也不该

用户问「咱们的项目能用 VB 吗」。**不能**，理由不是偏好，是架构：

* 我们这套是 **C11 核心 + C++17/Qt6 界面**，一份源码要出 **Windows / 安卓 / macOS / Linux**；
  VB(VB.NET) 只能配 WPF/WinForms 或 Unity，**等于把界面锁死在 Windows**，安卓那条线直接断（docs/18/19 已经铺到能起 JVM）；
* 核心/服务层（下载引擎、安装器、补全、隔离、取证）是**纯 C**，界面换成 VB 就得再写一层 P/Invoke 胶水，
  而我们现在的 Qt 层已经是"薄壳"；
* PCL 是 VB 这门语言 + WPF 的产物，**它的"手感"我们要学，它的技术栈不用抄** —— 手感来自
  布局纪律、动效时长与曲线、组件形态，这些都写进 §1/§4/§9 了。

### 10.2 动画系统怎么落（用户最关心的一条）

三层，全部是 Qt 自带能力，不引第三方：

| 层 | 做什么 | 用什么 |
| --- | --- | --- |
| 控件属性动画 | 悬停抬升、按钮内阴影、卡片出现（透明度 + 8px 上移） | `QPropertyAnimation` + `QGraphicsDropShadowEffect`（阴影动画走自绘，不用 effect，避免性能陷阱） |
| 形态过渡 | 汉堡↔关闭、启动↔停止、展开↔收起、草方块↔红石 | `QPainterPath` + `QVariantAnimation` 驱动 0→1 形变系数（§9 的 morphicons 思路） |
| 页面/外壳过渡 | 子栏折叠（220ms OutCubic）、页面淡入（120ms） | 外壳持有**唯一**的动画时钟（`QEasingCurve` 集中定义），页面不许自己起动画 |

**纪律**：动效 ≤220ms、OutCubic、缩放 ≤1.02、**尊重"减少动态效果"系统设置**（Windows 的无障碍开关）、
每个动效都要能在 CI 里断言（几何 dump 或截图比对）。**看不见、验不了的动效不做。**

### 10.2.1 动画层要补的三件事（读了 PCL 的 ModAnimation.vb 之后定的；只学"有这三样"，实现全自研）

> 出处：`C:\dsh_work\dev\PCL\Plain Craft Launcher 2\Modules\Base\ModAnimation.vb`（53KB）。
> 用户 2026-09-26 口径：**"可以，补上吧，然后记得代码不要和 PCL 雷同就行"** ——
> 下面三条只借鉴"它有什么能力"，**接口命名、数据结构与实现一律自研**：
> PCL 那套是 VB/WPF 的 `DependencyProperty` 模型（`AaX/AaOpacity/AaScale…` + `AniEase*` 曲线族），
> 我们这边是 Qt 的属性系统 + 自绘控件，写成 `Anim::to(...) .then(...)` 这类**链式任务**，
> 不照搬函数名、不照搬枚举、不照搬 `AniData` 的结构。

1. **时间线编排**（PCL 的 `After:=True`）：一个 `Anim` 句柄支持 `.then(next)` / `.after(ms)` / `.parallel(group)`，
   让"先淡入、再抬升、最后出图标"是**一句话**，而不是回调套回调。
2. **自家缓动表**（PCL 有 `AniEaseInFluent/OutFluent/InoutFluent/InBack/OutBack/…` + `AniEasePower` 三档强度，
   还有一个按"初速+总时长+总距离"算的曲线）：我们要定义**自己的曲线表**（进出 Fluent 两档 + Back 系列 + 按初速的那条），
   并把它作为**全站唯一来源**（页面只写 `Ease::Out` / `Ease::Back` 这种语义名）。曲线形状自己调，不抄参数。
3. **列表错峰模板**（PCL 的 `AaStack(panel, Time:=100, Delay:=25)`）：`Anim::stagger(rows, 100ms, 25ms)` ——
   列表刷出来一行行冒出来。这一条对"看着现代"的贡献最大，且**必须做成模板**（几十行列表不许写几十个动画对象）。
4. **全局动效开关**：设置里一项"界面动效"（开 / 减弱 / 关），并与系统无障碍设置取**更严**的那个 ——
   对应 PCL 的全局动画开关，但走我们自己的设置键（`ui.motion`）。

**性能纪律（自研实现必须守住）**：一个列表里**同时存在的动画对象 ≤ 屏幕内可见行数**（滚出屏幕就停），
所有动画共用一个 `QTimer` 心跳（不做 N 个 `QTimer`），动画驱动的都是**自绘属性**而不是频繁 `setGeometry`。



## 11 交互原则 V3（2026-09-26 用户口径，**这是写代码时的硬约束**）

### 11.1 按钮最少化（第一原则）

用户原话：「你要记住一个原则叫**按钮最少化**」。

* 一屏里**最多一个文字主按钮**（主页就是 `启动游戏`）；其余动作一律是**图标**；
* 图标按钮**不做"带文字的按钮"**：PCL 的做法是 —— 鼠标悬停到**玩家名那一行**，行尾才浮出几个小图标
  （换皮肤 / 切换账号 / 更改名字），平时不占地方；我们照这个形态做（`HoverActions` 组件：
  悬停才出现、图标 20px、间距 8、tooltip 给人话）；
* 凡是"能被猜到的动作"，不写文字：齿轮=设置、★=收藏、⌄=展开、✕=关闭、微软 logo=正版、断线图标=离线。

### 11.2 账号卡（V3）

## 12 从"老侧边栏叠层实验台"里攒到的三条经验（2026-09-26，都已搬进老界面）

这个 demo（`tools/rails_demo`）的意义是**累积经验**，不是做个玩具。三条结论都有实测数据：

1. **分隔线不能是一个控件**。用 1 逻辑像素的控件当线：在 **dpr=1.5** 的屏幕上它会占
   **1~2 个物理像素** —— 真机截图扫列实测相邻边界一条 2px、一条 1px（肉眼"一粗一细"）；
   而 `QFrame::VLine` 更糟：Fusion 的默认调色板是浅色的，深色界面里直接画成**白线**。
   **正解**：栏与栏**零间距**相邻，线由**容器**在 `paintEvent` 里用 `QPen(color, 0)`
   画（宽度 0 = cosmetic = 恒定 **1 个设备像素**），颜色取主题令牌 `line`。
   老界面这次去掉了 `beginSideLayout` 里那条 `row->setSpacing(12)` —— 那道"肉眼可见的隔阂"就是它。
2. **"同一时刻最多一条栏展开"必须是外壳的状态机**。栏只上报 `collapsedChanged`，
   外壳（`MainWindow::registerRail`）负责把别的栏收起来；页面与栏自己不许持有这个状态。
   实测（demo）：三条栏各自为政时 `展开条数=3`；加了状态机后每次都是 `展开条数=1`（全收起=0 也合法）。
3. **交互只能有一条时间线**。跟随重绘与"落定判定"必须挂在**状态变化**上（常开定时器 + 宽度变化探测，
   16ms 一次），不能挂在某个调用入口上 —— 否则"手点"与"程序调用"就是两条时间线
   （用户 2026-09-26 实测:「还是慢啊…你自动互动的时候不慢」就是这么来的）。
   同理，**判词/日志只在落定后出**（demo 里是"连续 240ms 宽度没变"），动画中途不判 —— 否则
   量到的是过渡态（`w=321`、`缝隙=-1`），自己制造假 FAIL。

**老界面：这三条都已落地并真机验收**（2026-09-26，命令见 `tools/ui_rail_assert.ps1`）：

* 状态机与登记：`MainWindow::registerRail` + `registerPageRails`（**每一处建页都登记**；页面重建自己的
  侧栏时由页面再登记一次）。修掉了两个实测漏洞：下载页那条侧栏（构造期就建好的常驻页）从来没进过
  状态机（展开主栏后**展开条数=2**）；版本选择页换文件夹后新 `NavPanel` 也没登记（同样 =2）。
  另外**只认看得见的栏**：页面构造期就把侧栏展开，让藏着的页参与"最多一条展开"会把当前页那条真
  在用的栏收掉（实测 route=select 启动后侧2 被顶成 48）。
* 分隔线：容器 `MainWindow::paintEvent` 用 `QPen(separator, 0)` 画 1 **设备**像素，叠在内容栈
  那层半透明 border 底下透出来（深色下这一列实测 **48**；只叠那层 border 会得到 26 ——
  线确实是我们画的，不是 border 自己）。页面自己那 1px `QScrollArea`
  原生 frame 已去掉（`PageShell` 里 `setFrameShape(QFrame::NoFrame)`）—— 它就是页面与侧2 之间那 1px。
* 实测数字（`sxcl-ui.exe`、本机 dpr=1.5、`SXCL_UI_ROUTE=select`、`SXCL_UI_DUMP=1`）：

  侧2 `(49,49 322x677)`；`1280x800` 页面 `(49,49 1231x751)` / 侧2 `(49,49 322x727)` —— **dx=0 dy=0**。

### 12.1 切页收敛（2026-09-26 收尾；口径：**页面自己的侧栏优先**）

**口径（产品已拍板）**：切进某一页时，**那一页的侧栏在该页是展开态** -> 收起**主栏**（让位给页面
侧栏）；反过来，用户把主栏展开时，页面里那条可见的侧栏让位（这一半由上面那套状态机管）。
目标始终是：任一时刻**"可见且展开"的栏数 <= 1**（全收起 = 0 也合法）。

**为什么原来的状态机收不到这一步**：钩子挂在 `NavPanel::collapsedChanged`（**状态变化**）上，
而**生来就展开**的页内侧栏（版本选择页 #sxclVersionFolderNav / 下载页 #sxclDownloadNav，
两者都在构造期 `setCollapsed(false)`）在"切到这一页"那一步**没有任何状态变化** —— 没有信号可接，
外壳无从知道。

**实现**：

* `MainWindow::convergeRails(NavPanel *preferred)` 是**唯一**的收敛入口：preferred **展开且可见**
  （`isVisibleTo(window())`）-> 把其它**可见且展开**的栏收起（**主栏在内**）；preferred 为空、收起、
  或藏着 -> **一行都不动**（绝不主动展开任何栏）。幂等、不递归（收起不会再走展开那条分支）。
* 调用点挂在**内容栈**的 `currentChanged` 上（**不是**挂在 `switchToRoute` 这个入口上：导航项、
  临时页、会话页恢复都过这一处，不存在"还有一条路没接上" —— 同 §12 第 3 条）。
* 真正那次收敛用 `QTimer::singleShot(0, ...)` **推迟一拍**：等页面真的可见再判；回调里**重新问一次**
  当前页（连切两页只收敛最后那一页）。**构造期不做**（那时窗口还没 `show()`，"看得见的栏"是空集，
  做了反而会把当前页那条正在用的栏连锁收掉）。窗口从托盘回来时也再收敛一次（藏着那段时间可能换过页）。

**实测（`build-ui` Release / `sxcl-ui.exe`、1100x750、本机 dpr=1.5、`SXCL_UI_RAILS_TEST=1`）**：
"修前"这一列是把 `convergeRails` 那一行注释掉、**重新编译同一个 exe** 量出来的（不是推测）；
"修后"这一列是恢复后重新编译量的：

| step | 动作（都是产品路径） | 修前 expanded / nav / sub | 修后 expanded / nav / sub |
| --- | --- | --- | --- |
| 0 | 起点（route=select） | 1 / 48 / 322 | 1 / 48 / 322 |
| 1 | 切回版本选择页 + 确保侧2 | 1 / 48 / 322 | 1 / 48 / 322 |
| 2 | 展开主栏（状态机收侧2） | 1 / 322 / 48 | 1 / 322 / 48 |
| 3 | **切到下载页** | **2 / 322 / 322**（`who=sxclNav,sxclDownloadNav`） | **1 / 48 / 322**（`who=sxclDownloadNav`） |
| 4 | 切回版本选择页 | 1 / 322 / 48 | 0 / 48 / 48 |
| 5 | 版本选择页再展开侧2 | 1 / 48 / 322 | 1 / 48 / 322 |
| 6 | 再切下载页（侧2 这时**藏着**且展开） | 1 / 48 / 322 | 1 / 48 / 322 |
| 7 | 再切回版本选择页 | 1 / 48 / 322 | 1 / 48 / 322 |

* step3 就是那条已知边界：**主栏 322 + 刚露出来的下载页侧栏 322 = 两条**（修前实测 expanded=2，
  `who` 把两条名字都打了出来）；修后外壳在这一步打一行
  `[rails] converge: preferred=sxclDownloadNav -> 收起 1 条可见且展开的栏`，主栏让位（322 -> 48）。
* step6 验"**藏着的栏不参与**"：版本选择页那条侧栏此刻还展开着（322）但整页藏着，expanded 只算
  看得见的 -> 1（不是 2），也**没有**被顺手收掉 —— 切回 step7 时它仍是唯一一条展开的。
* 修前 step4 是 1（主栏还 322）：那是"两条"被后面那次展开动作顺带收掉的结果，不是收敛 ——
  修后 step4 是 0（两条都已收起，且**不主动展开**）。
* 断言脚本（`tools/ui_rail_assert.ps1`，全 ASCII + UTF-8 BOM）现在按上面这张表逐步断言：8 条读数、
  每步 expanded <= 1、step3 的 route/name/nav/sub、step4 = 0、step5..7 的宽度；三次运行
  （select / download / select+换文件夹，临时目录 `D:\SilentStudio\_test\rail_assert`）末尾打印
  `RAIL-GEOMETRY: ALL OK`。

### 14.1 先量清楚:那条"未响应"到底是什么

* **看门狗自己坏了(假报告的根因)**。`installHangWatchdog(3000)` 在 `main.cpp` 里是

### 14.4 这一轮踩到的坑(记着,别再走)

1. **"先建一条栏、探测回来再重建"会把状态机搅乱**。侧栏重建会造出第二条 `NavPanel`
   (老那条还在 `deleteLater` 队列里),外壳的 `registerRail`/`convergeRails` 与
   `SXCL_UI_RAILS_TEST` 的读数都会跟着抖 —— 实测 route=select 的侧2 被顶成 **48**、
   step2 的 `expanded` 变成 **2**(正确值:322 / 1)。
   **正解**:探测结果回来**只建一次**侧栏(§12 第 3 条"交互只能有一条时间线"的同一族问题:
   别让同一条 UI 状态有两条产生路径)。
2. **看门狗的跳表必须在 QApplication 之后、`app.exec()` 之前武装**
   (`armHangWatchdog()`)。装机早于事件分发器 = 定时器不存在 = 假报告。
3. **假报告比没有报告更贵**:它会把三次正常启动"证明"成三次卡死,
   于是所有人(包括我)都去追那条无辜的 HTTP 请求。取证工具自己也要有验收。



## 13 用户 2026-09-26 追加的两条硬要求（写进方案，别再漏）

### 13.1 动画系统要"完善掉"（不是够用就行）

按 §10.2 / §10.2.1 落地，缺一不可：
1. **时间线编排**：`Anim::to(...).then(...).after(ms).parallel(group)` —— 页面里不许回调套回调；
2. **自家缓动表**（进/出 Fluent、Back、按初速那条），页面只写 `Ease::Out` 这类语义名；
3. **列表错峰模板** `Anim::stagger(rows, 100ms, 25ms)`（"一行行冒出来"），必须模板化；
4. **全局动效开关** `ui.motion`（跟随系统 / 标准 / 减弱 / 关闭），与系统无障碍取更严的那个；
5. **性能纪律**：同时存在的动画对象 ≤ 屏幕内可见行数；所有动画共用一个心跳定时器；
   动画只驱动自绘属性，不频繁 `setGeometry`；
6. 每个动效都要能在 CI 里断言（几何 dump 或截图比对）—— 看不见、验不了的动效不做。

### 13.2 默认排版格式：**居中竖线 + 左右两枚图标**（以下载页 Java/基岩 切换件为样板）

用户原话：「下载栏儿现在 Java 和基岩版的切换，你给我居中放一条中文中的这个竖横线，
然后左侧是咖啡杯，右侧是基岩…点这两个所代表的图标，而不是一个按钮，非常诡异」。

* 形态：`[图标A] │ [图标B]` —— 中间一条**竖直分隔线**（容器 `paintEvent` + `QPen(line, 0)`，
  恒定 1 个设备像素，**禁止** `QFrame::VLine`，理由见 §12），两颗图标**各自可点**，
  选中态用**主题令牌**表达；**不加文字标签**，信息放 tooltip；
* 图标口径（我查过：官方 Java 咖啡杯是商标、Bedrock 也没有可直取的正版素材，不为它冒版权风险）：
  **Java = 自有图标集里的 `Cafe`（咖啡杯，单色跟随主题）**；**Bedrock = 自绘
  `assets/icons/blocks/Bedrock.png`**，风格与 `blocks/` 下现成 13 枚完全一致；
* 这条**升格为默认排版格式**：以后凡"二选一"的切换件都照这个做（图标 + 居中竖线 + 点选 + 令牌高亮），
  不再用滑块/开关/带文字的按钮；
* 顺手删掉那类"解释功能没接入"的废话文案（只许放 tooltip 或折叠区）。
