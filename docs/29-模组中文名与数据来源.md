用户 2026-09-27 原话：

> 「有 PCL 对某些模组是有中文名的，我不知道他怎么做的，应该不是直接在本本地翻译，你看看能不能做。」

**结论：能做，而且形态就是 PCL 那个形态 —— 一张随包带的本地表，不是运行时翻译。**

许可证、覆盖量估计逐条列在下面，最后是我们选了谁、为什么，以及没选的为什么没选。

### 2.1 CFPA 那条"很多包有 `modmenu.nameTranslation.<modid>`"**实测不成立**（这条值得单独记）

用户给的线索里写着"它里面很多包有 `modmenu.nameTranslation.<modid>` 这类键"。本轮把 CFPA 全仓的
语言文件都拉下来数了一遍（稀疏检出，只取 `projects/assets/*/*/*/lang/*.json`）：

* **11108 个语言文件里，只有 4 个**含 `modmenu.nameTranslation.*`（其中 2 个还是 Mod Menu 自己的包）；
* 成品包也数了：`Minecraft-Mod-Language-Modpack-1-20.zip` 里 596 个 `zh_cn.json`，
  `modmenu.nameTranslation.*` **0 个**；1.21 / 1.21-Fabric 同样是 0。

原因：CFPA 的语言文件是"**改动过的键**"（overlay），而 `modmenu.nameTranslation.<modid>` 是模组作者
写在**自己 jar 的语言文件**里的；作者没写、CFPA 也没补的模组，这里就没有。所以 CFPA **能提供翻译**
（一堆 `xxx.tooltip` 之类），**提供不了"这个模组叫什么"**。

> 这条同时也解释了为什么"随便找一份汉化包就行了"是不成立的 —— 得专门找**名字表**。

## 3 我们采用的那份：HMCL `mod_data.txt`

格式：`curseforge_slug;mcmod_id;modids(逗号分隔);中文名;英文名;缩写`，例如

```
industrial-craft;2;IC2,ic2;工业时代2;Industrial Craft 2;IC2
applied-energistics-2;...;ae2;应用能源2;Applied Energistics 2;AE2
```

我们的处理（生成器 = `tools/modnames_build.py`，逐条写在 `assets/data/modnames.NOTICE.md`）：

| 处理 | 数字 |
| --- | --- |
| 上游展开 `modid` 之后的候选行 | 29764 |
| 丢掉"中文名里没有汉字"（就是英文原名，例如 `Fabric API` → `Fabric API`） | 17207 |
| 丢掉"一个可查键都没有" | 58 |
| **最终条数** | **12497** |
| 不同模组数 | 11660 |
| 带 `modid` 的条数 / 带 `cf_slug` 的条数 | 11946 / 8832 |

**为什么丢掉"没有汉字"的行**：那些行的"中文名"与英文原名一模一样（`Fabric API`、`Cloth Config API`、
`GeckoLib` …）。收进来只会让界面把原名再显示一遍，还会让"有中文名 +0.2"这类排序权重失真。

## 5 机制（这一轮做出来的东西）

### 5.1 表与查表

* 表：`assets/data/modnames.tsv`（TSV，UTF-8，表头是 `#` 注释行；格式与云端那份**完全一样**）；
* 代码：`include/sxcl/modnames.h` + `src/services/modnames/modnames.c`（纯逻辑，不联网、不碰界面）；
* **三键查**（用户点名的）：`Modrinth slug` / `CurseForge id` / `项目名`；另外还有 `cf_slug` 与 `modid`
  两个键（本地 jar 的 modid 直接能查）。查表顺序：slug → cf_slug → cf_id → 名字；
* **查不到返回空**：命中返回表内部的中文名指针，没命中返回 NULL；给界面用的 `sxcl_modnames_apply()`
  在没命中时**一个字都不写**（调用方传进来的原名原样留着）；
* **绝不猜**：没有拼音、没有机翻、没有模糊匹配（规范化只有"大小写 + 空白/标点"这一种，中文按 UTF-8 原样比）；
* **O(1)**：建表时一次性建开放寻址哈希（负载因子 ≤ 0.5），`sxcl_modnames_last_probes()` 把"这次查了几个槽"
  暴露出来 —— 单测在 **20000 行**的表上断言命中/未命中都 ≤ 8 个槽位（不是掐表，是数槽）；
* **不崩**：空表、空指针、坏行（列不够 / 中文名为空 / 超长行）、缺列（`# columns` 只给一部分）、
  表头条数或 sha256 对不上 —— 全部有单测；坏行**数出来**（`sxcl_modnames_bad_lines`），不静默。

### 5.2 云端更新（契约写在 `docs/28`）

* 路径：`${BASE}/meta/modnames.tsv`（与随包同一格式，带 `version` / `count` / `sha256`）；
* 接受条件**三条全过才换**：是合法的表 + 表头声明的 sha256/条数与正文对得上 + `version` 比手上那份新；
* 换法：先写 `<缓存目录>/meta/modnames.tsv.part`，校验通过后**原子改名**替换；
* **失败就是失败**：缓存原样不动、继续用随包那份，返回值与 note 如实说清（拿不到 / 不是我们的表 /
  摘要对不上 / 版本没前进 / 没有传输后端，各有各的话）；
* 启动时挑表的顺序：**校验过的缓存（且 version 比随包新）→ 随包**；两份都没有 = 空表（不阻塞启动）。

### 5.3 界面怎么用（这一轮**不碰界面**）

界面侧只要两件事（接线由模组页那一轮做，这里只给函数）：

```c
const char *zh = sxcl_modnames_lookup(table, hit.slug, cf_id, hit.title); /* 或 */
sxcl_modnames_apply(table, hit.slug, cf_id, hit.title, buf, sizeof buf);  /* 命中才改写 */
```

随包表路径由调用方给资产根：`sxcl_modnames_bundled_path(asset_root, ...)`（`<assets>/data/modnames.tsv`，
环境变量 `SXCL_MODNAMES_FILE` 优先，取证/验收用）；缓存在 `<数据目录>/meta/modnames.tsv`。

## 6 没做的、与残余风险

* **界面接线没做**（用户这一轮明确说"不要碰界面"，且模组页正被另一个改动占着）：本轮的交付是
  "能被界面调用的查询函数 + 表 + 生成器 + 覆盖率报告 + 云端契约"；
* **"有中文名 +0.2 排序权重""中文名当搜索别名""保存成【中文名】原文件名.jar"三条没做**：
  逐条记在 `docs/22`，标了"做 / 不做 / 待定"（保存文件名的形态**不许**因为我们这份表而改变，见那条）；
* **残余风险（必须写清）**：上游那份数据的文件头把内容版权写给 mcmod.cn，我们只是"HMCL 以 GPL-3.0 分发、
  我们逐行保留 mcmod 编号"这一条链。若上游主张权利，**删掉 `assets/data/modnames.tsv` 即可**
  —— 缺表路径有单测，客户端只是"这次没有中文名"，不会报错也不会阻塞启动；也可以换成云端那份，
  不用发版（见 `docs/28`）。
