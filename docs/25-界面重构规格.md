## 2 主页（`home`）

| 区块 | 内容 | 数据来源 / 状态键 |
| --- | --- | --- |
| 标题 | `主页` + 副标题（启动器名+版本） | 原样 |
| **当前版本** | **大号显示"当前游戏版本名"** = `versions/` 下的**文件夹名**（可自定义、和 MC 版本号无关），右侧一个 `更换` 按钮 | 新增状态键 `game.selected_version`；没有就取扫描到的第一个 |
| 启动区（左右两半） | 左：**正版启动**（已登录：头像+名字+`启动`；未登录：`登录`按钮）<br>右：**离线启动**（`ID` 输入框 + `启动`）<br>已登录的玩家也**可以**走离线启动（用户明确要求） | 账户快照走 `dialogs/account.*`；离线 ID 新增状态键 `launch.offline_name`（默认 `Player`） |
| 游戏目录 | 当前文件夹**完整路径** + `选择目录` | 已有（`game.default_dir` + 文件夹探测） |

**砍掉**：原来铺满主页的"所有已安装版本卡片"（`home_page.cpp` 的 `renderCards()`/`createVersionCard()`）→ 全部搬进版本选择页。

**为什么"改文件夹名/改 jar/json 里的 id 都不影响启动"**（用户问的原理，写进代码注释）：
我们启动一个版本靠的是**三件事各自独立**——① 目录名 = 实例名（`versions/<实例名>/`）；
② 该目录里**任意一份能解析出 `mainClass`+`type`+`id` 的 JSON**（`sxcl_instance_read_json`，PCL 的兜底规则：同名优先，否则取目录里第一份像版本 JSON 的）；
③ 那份 JSON 里的库/客户端 jar 按**路径**去找，而不是按 id。所以文件夹叫 `114514`、JSON 里的 `id` 也叫 `114514` 都能跑，
真正决定"启动的是哪个版本"的是 JSON 里的 `libraries`/`mainClass`/`assetIndex`/`inheritsFrom`（我们已在 `docs/23` 把它拍平成自包含的一份）。

## 3 版本选择页（`select`）

**布局**：左右两栏。

* **左栏：文件夹列表**（"当前文件夹"在最上，选中态）
  * 候选来自现有探测逻辑（`home_page.cpp` 的 `folders.py:112-151` 移植：启动器目录（便携）→ 官方启动器（APPDATA）→ 用户目录 → 桌面……），
    每个文件夹显示**它自己的名字**（`QDir(path).dirName()`），**不强制叫 `.minecraft`**；
    "当前文件夹"= 正在使用的那个（`game.default_dir`），行里同时显示版本数与完整路径（tooltip）；
  * 底部一个 `导入文件夹…`（用户手动选目录，落进候选历史）。
* **右栏：该文件夹下的已安装版本**：一行一个，显示**文件夹名**（大）+ 加载器标签 + 问题提示（`sxcl_instance_scan` 给的 `problem`）。
* 点一行 = **设为当前版本**（写 `game.selected_version`）→ 自动回主页。
* 顶部一行小字：`当前文件夹：<名字>`。

> 用户说的"导入历史"= 上面那份候选列表的持久化：新增状态键 `game.known_dirs`（多值，分隔符与设置模块一致）。

## 7 更多（`more`）

一个入口列表（卡片行，每行：图标 + 标题 + 一句说明 + 右侧箭头）：

| 入口 | 去向 | 说明 |
| --- | --- | --- |
| **按键映射** | `keymap` | 用户点名：手机键位归到"更多"；**电脑端用户通常不用**，所以我们支持**端游制作键位 + 一键复制键位码 + 导入键位码**（见 §7.1） |
| 下载任务 | `tasks` | 原"任务"页 |
| 崩溃与日志 | 设置页的日志导出入口（或独立对话框） | 已有 `sxcl_logexport` 能力 |
| 关于 | 对话框 | 版本号/构建时间/日志路径 |

### 7.1 按键映射的两件新事（用户点名）

1. **一键复制键位码**：把当前键位方案序列化成一段可粘贴的"键位码"（含方案名 + 版本，形如 `SXCLKM1:<base64>`，与 `keymap_store` 的落盘格式同源，避免两套序列化）；
2. **导入键位码**：粘贴框 + `导入`，解析失败如实报错（不覆盖现有方案，导入成新方案）。
   * 这两条对**电脑端**同样有用（端游用户也能导出一份键位发给别人），所以放在按键映射页顶部，不做平台判断。
