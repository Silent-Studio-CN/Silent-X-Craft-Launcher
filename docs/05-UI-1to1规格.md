## 10. 实测确认的渲染规则（2026-xx 更新，全部有出处）

### 10.1 卡片底色 = 半透明白，不是不透明色值
qf `components/widgets/card_widget.py:37-38,115-116`：
```python
def _normalBackgroundColor(self):  return QColor(255, 255, 255, 13 if isDarkTheme() else 170)
def _hoverBackgroundColor(self):   return QColor(255, 255, 255, 21 if isDarkTheme() else 64)
def _pressedBackgroundColor(self): return QColor(255, 255, 255,  8 if isDarkTheme() else 64)
```
- 叠在窗口底 `#202020` 上 → **(43,43,43) = #2b2b2b**，正好等于令牌 `card`（令牌就是这么推出来的）。
- 浅色叠在 `#f3f3f3` 上 → 约 `#fbfbfb`（注意令牌 `card` 写的是 `#ffffff`，Python 端两者本就不等）。
- 卡片圆角 qf 默认 **5**（`getBorderRadius`）；SXCL 的 `card_qss` 覆盖为 **8**。
- **所以卡片要用半透明底实现**，写死不透明 `#2b2b2b` 会在浅色主题和悬停态下错。

### 10.2 内容区底色 = 窗口底 `#202020`
- SXCL `theme.py:191-196 global_qss()` 明确写 `QScrollArea, QStackedWidget { background: transparent }`。
- qf 开 Mica 时窗口背景由系统画 → 透明处会**透出桌面**（这就是"参考图内容区变成 #1e1e1e、卡片变成 #292929"的全部原因：桌面 30 + 白 5.1% = 41）。
- **结论**：设计值就是 `#202020`；抓参考图时必须让窗口/页面不透明（见 §11）。

### 10.3 外壳几何（页面可用区）
Python 参考图实测：页面在窗口内 **(48,48)，尺寸 1052x702** = 1100x750 − 标题栏 48 − 导航 48，**无任何额外边距**。

### 10.5 qf 页面切换的正确调法（踩坑）
```python
w.switchTo(page)                              # ← 真正切页
w.navigationInterface.setCurrentItem(name)    # ← 只改选中态,不切页
```
原因：`addSubInterface(..., onClick=lambda: self.switchTo(interface))` —— 切换挂在导航项点击回调上。
（给 `stackedWidget` 设样式表也不会切页，别用它当"钉底色"的手段。）

### §11 补充：验收口径三条硬规则（2026-xx，踩过坑才定下来的）

1. **强调色传原始色**：`SXCL_UI_ACCENT` 是**配置里的原始色**（Python `qconfig.themeColor` 同义），
   不是渲染值。参考机配置是 `#c044a3`，qf 暗色推导（`s*=0.84, v=1`）后才是参考图上的 `#ff75df`。
   传 `#ff75df` 会被再推一次变成 `#ff8be4`（按钮底色整块错，吃掉 2 个点）。
   `FluentTheme::accent()` 返回**推导后**的值（对齐 Python `theme.py:135/168`），`rawAccent()` 才是配置原值。
2. **参考图流程必须调 `apply_theme()`**：Python `main.py:150` 会调它（装库主题 + 应用调色板 + global_qss）。
   以前抓图漏了这步 → 参考图没有 global_qss，而 C 版一直装着等价的应用级 QSS，两边口径不一致
   （实测：download_config 的输入框因此差 9px，整页差 1.2 个点）。现已补进 `tools/grab_reference_ui.py`。
3. **不设应用字体**：Python `main.py` 只做 `app.setStyle("Fusion")`，**从不 `setFont`**；
   qf 的字体只通过 QSS 的 `--FontFamilies` 影响 qf 控件，原生控件用系统默认
   （`Microsoft YaHei UI` 9pt，fmh=15）。我们以前在 `FluentTheme::apply()` 里设 `Segoe UI`（fmh=16）
   → 每个原生控件高 1px、页面自上而下累计错位 1~2px。**已删除该覆盖**。

**当前全量数字（9 页，深色，原始色 `#c044a3`，参考图同口径）**：
tasks 0.00% / download_progress 0.01% / launch 0.01% / home 0.09% / multiplayer 0.15% / keymap 0.21% /
settings 0.98% / versions 1.54% / download_config 2.33%。

4. **绝不要给 `StackedWidget` 补 `background-color: transparent`**：那层底色就是"画圆角的笔"。
   qf 规则（`qf_exact/dark/fluent_window.qss:63-69`）的 `background-color: rgba(255,255,255,0.0314)`
   铺在窗口底 `#202020` 上 = `#272727`，它露出的那半像素正是**内容框左上 10px 圆角里侧的 1px 亮带**。
   我们曾在外壳里用**控件级** QSS 追加 transparent 抹掉它（应用级 transparent 压不过控件级 qf 规则），
   结果圆角看着被抹平成直角 —— 用户报的"左边栏和上边栏组成的圆角被主页面遮住"就是这个。
   **正确做法**：栈保留 qf 底色 + 1px 边框 + 左上圆角；**每个页面自己钉不透明底色**
   （`QWidget { background: <token bg> }`，与 Python `BasePage` 行为一致），
   顺带还能让页面自己的 StyledPanel 1px 边框回来（实测整圈边框 32→25，与设计逐像素相同）。
   固定判据：`python tools\ui_corner_probe3.py` 两级灰度图必须完全一致。

6. **用户点名的两处 UI 偏离(2026-09-21,别当成 bug 改回去)**:
