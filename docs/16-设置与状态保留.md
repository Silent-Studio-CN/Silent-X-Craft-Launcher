# 设置与状态保留(为什么"设置关闭重开打回原形"会发生,以及现在怎么保证不再发生)

> 用户报障原文:"不光是源切换有问题,整个程序的设置,状态保留都有问题,还要设置关闭重开直接打回原形。"

## 1. 根因:同一个设置文件有**三个各自手拼的路径**

| 谁 | 平台 | 路径 |
| --- | --- | --- |
| 设置页(**写**) | Windows | `%APPDATA%\SilentXCraftLauncher\settings.conf` |
| 设置页(**写**) | Android | `<应用私有 files>/SilentXCraftLauncher/settings.conf` |
| 界面读取方(游戏目录 / Java / 内存 / 下载源 / 启动恢复主题语言) | Windows | 同上(碰巧一致) |
| 界面读取方 | Android | `~/.config/SilentXCraftLauncher/settings.conf` —— **安卓 HOME 是 `/`** |
| 账户模块 | Android | 同上一行 |

Android 上"HOME"在启动器入口里被设成应用私有 files 目录,所以读取方实际找的是
`<files>/.config/SilentXCraftLauncher/settings.conf` —— 那个文件**从来没有被创建过**。
于是:设置页改了、界面上看着也改了,重启之后启动恢复(主题/强调色/语言)、游戏目录、Java 路径、
内存、下载源**全部回落默认值**。桌面永远不会暴露这个问题(三个路径碰巧同值),Linux 也有同类错位
(核心库按 XDG 用小写目录名,手拼那份用大写)。

## 2. 现在的规矩:路径**只有一个权威**

`sxcl::ui::uiSettingsFilePath()`(src/ui/workers/ui_paths.cpp)是唯一入口,它内部就是核心库的
`sxcl_settings_default_path()`:

| 平台 | 目录(核心库定) |
| --- | --- |
| Windows | `%APPDATA%\SilentXCraftLauncher` |
| Android | `$SXCL_ANDROID_FILES/SilentXCraftLauncher`(打包层设的私有 files 目录) |
| macOS | `~/Library/Application Support/SilentXCraftLauncher` |
| Linux | `$XDG_CONFIG_HOME/silentxcraftlauncher` 或 `~/.config/silentxcraftlauncher` |

- `SXCL_CONFIG_DIR`(核心库)与 `SXCL_UI_SETTINGS`(界面)是**取证覆盖**,生产路径不设。
- 缓存/清单/pending_tasks.json 都挂在**同一个目录**(uiLauncherDataRoot()),不再另起一处。
- **新代码读设置一律走这两个函数**,不许再手拼路径 —— 这次事故就是这么来的。

## 3. 下载源(download.source):默认 BMCLAPI,官方不通自动切

- 键:`download.source`,取值 `bmclapi`(默认)/ `auto` / `mojang`;设置页"版本下载源"下拉。
- 读取方:`sxcl::ui::uiDownloadSource()`(默认返回 bmclapi;Python 版"重置设置"落地写的也是 bmclapi)。
- **清单(版本列表)**:候选顺序按源排,第二条候选就是"自动切":
  - `bmclapi`/`auto` -> BMCLAPI 优先,不通自动切官方;
  - `mojang` -> 官方优先,不通自动切 BMCLAPI。
  超时分路给:官方 **20s**、镜像 **8s**;走第二条路且第一条是官方时,弹 InfoBar
  "官方源超时(等待 20 秒未完成),已自动切换到 BMCLAPI 镜像源"。
- **游戏文件(jar/依赖库/资源对象/加载器安装器)**:核心库 `sxcl_version_plan_prefer_mirror()`,
  见 docs/15-下载源与镜像优先.md(含实测的来源下标直方图)。
- 取证入口:`SXCL_UI_MANIFEST_OFFICIAL`(把"官方源"这个位置换成任意地址,用来确定性复现超时切换)、
  `SXCL_UI_MANIFEST_URL`(钉死单条地址,测"两条都不通 -> 退缓存")。

## 4. 怎么证明(可重复的验收命令)

```powershell
# 源顺序三例 + 设置文件读写一致性(write2 那例:埋一个越界内存值,设置页会纠回并落盘)
powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify_download_source.ps1
```

实测输出(2026-09-21,桌面离屏,真清单):

| 用例 | 结果 |
| --- | --- |
| 没写过 download.source | `清单源=bmclapi` -> 清单 OK **915** 个版本 |
| `download.source=mojang` | `清单源=mojang` -> 清单 OK 915 |
| `mojang` + 官方地址换成 `http://127.0.0.1:9/dead` | 日志 `官方源超时 -> 已切换 BMCLAPI`,清单 OK 915 |
| 埋 `game.max_memory_mb=1` + `ui.theme=dark` | 启动日志 `主题: 深色(mode=dark)`;文件被改成 `game.max_memory_mb=2048`(读写同一个文件) |

## 5. 顺带修掉的两处"状态留不住"

1. `install_worker` / `launch_worker` 里 `QThread` 带了 parent,Qt 拒绝 `moveToThread`
   (日志:`QObject::moveToThread: Cannot move objects with a parent`)—— 工作线程根本没搬走,
   界面会卡。现在线程对象没有 parent,由 worker 析构负责 `quit + wait + delete`。
2. 版本页清单缓存路径以前直接拼 `%APPDATA%`,APPDATA 为空(安卓必然为空)时缓存路径整个消失,
   远端不通连兜底都没有。现在缓存挂在启动器数据根下,写之前先 `mkpath`。
