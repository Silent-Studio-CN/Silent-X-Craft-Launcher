# 总体设计

## 1. 模块划分与 Python 版对应

| 本工程 | Python 版对应 | 职责要点 |
| --- | --- | --- |
| `src/core/dl/engine.c` | `src/core/download/engine.py` | 任务编排、多连接 Range 切分、`.part`/`.part.json` 续传、失败重试与退避 |
| `src/core/dl/limiter.c` | `src/core/download/limiter.py` | 全局 + 单任务令牌桶限速，单调时钟，丢令牌缺陷已在 Python 版修正，C 版直接实现正确语义 |
| `src/core/dl/verify.c` | `src/core/download/verify.py` | 流式 SHA-1/SHA-256，边下边算，失败即弃用并切换线路 |
| `src/core/dl/spec.c` | `src/core/download/spec.py` | 下载项描述（URL、大小、哈希、目标路径、优先级、是否硬校验） |
| `src/core/router.c` | `src/core/net.py` + `health.py` + `source_stats.py` | 官方 / BMCLAPI 双路、镜像专属路径改写的尾段路由、熔断、来源 EMA 打分 |
| `src/core/settings.c` | `src/core/settings.py` | 配置读写（与 Python 版同文件同键名，双向兼容） |
| `src/services/version/` | `src/services/minecraft/` | 版本清单、库/资源索引、加载器识别（PCL 命名、`clientVersion`、HMCL 补丁、缺失父版本） |
| `src/services/loader/` | `src/services/mod_loader/` | Forge/NeoForge 静默安装（方式 A：`--installClient`；方式 B：PCL 式解包）、OptiFine 临时 APPDATA 沙箱、兼容性判定 |
| `src/ui/` | `src/app/` | 页面结构、主题令牌、动画节奏，全部走 libqf |

## 2. 线程与 IO 模型

- 主线程只跑 UI 事件循环；所有网络与磁盘任务在工作线程池上执行，结果经无锁队列回投。
- Windows 用 IOCP，Linux/Android 用 epoll；每任务一个状态机，避免线程爆炸。
- 下载 worker 数量按 `min(8, CPU*2)`，单任务连接数默认 4（可配），限速在写入前统一节流。

## 3. 内存与错误模型

- 核心库零全局可变状态：`sxcl_ctx` 显式传递，便于测试与多实例。
- 热路径使用 arena + 定长缓冲；大文件流式处理，任何路径不得整文件入内存。
- 错误统一为 `sxcl_err`（枚举 + 线程局部消息缓冲），不抛异常、不返回裸 NULL 语义。

## 4. 校验契约

- Mojang 提供哈希者一律强校验（SHA-1），校验失败不落盘为正式文件，计入线路失败并换线重试。
- 校验结果写入本地哈希缓存（含 mtime + size 作为弱指纹），避免重复计算。
- 镜像返回的文件若哈希不符，视为线路故障，触发熔断计数。

## 5. 与 Python 版的数据互通

- 配置文件、实例列表、键位方案、PCL 兼容文件全部沿用既有格式，切换版本不丢数据。
- 回归测试用纯 C 测试读取黄金文件（`tests/golden/*.json`，纯数据生成物）：同一输入下产出的清单、路径、哈希必须逐字段一致。
- Python 版只在"确认语义"这一步被阅读，不参与构建、测试、打包，也不作为运行时依赖。
