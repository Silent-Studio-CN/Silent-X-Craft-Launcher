# 迁移路线

每个阶段都必须有可运行的验收命令，验收不通过不进入下一阶段。

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 0 | 骨架、CMake 预设、编译机（WS2025）跑通空库 + 单元测试 | `ctest` 全绿；`libsxcl` 静态库产出 |
| 1 | 下载引擎：多连接 Range、续传、令牌桶限速、流式校验、哈希缓存 | 与 Python 版对拍同一 URL 的下载结果（大小、哈希、限速曲线）；断网续传成功 |
| 2 | 双路线路与熔断、镜像路径改写、来源打分 | 断掉官方线路后自动切 BMCLAPI 并在恢复后切回；日志与 Python 版语义一致 |
| 3 | 元数据层：版本清单、库/资源索引、加载器识别、PCL 目录结构适配 | 对本机真实 `.minecraft` 扫描结果与 Python 版逐字段一致 |
| 4 | 安装层：Forge/NeoForge 静默安装两种方式、OptiFine 沙箱、Fabric/Quilt | 端到端安装 Forge 1.21.11 成功并可启动（沿用 Python 版已验证结论） |
| 5 | 启动层：参数拼装、Java 探测、进程守护与日志解析 | 用真实 Java 启动实例成功（需有真实 GPU 的机器） |
| 6 | UI：Qt6 + libqf 复刻现有页面与主题令牌 | 与 Python 版截图逐页比对，键位映射页与安卓端行为一致 |
| 7 | 基岩与联机（Rust）：版本管理、微软/离线登录、联机 | 登录成功、联机握手成功；不下载、不分发第三方基岩安装包 |
| 8 | 打包：Windows 安装包（Inno，含 Qt 运行时）、便携包、安卓 APK | 三端产物在干净机器上安装即用 |

## 与 Python 版并行维护的约定

- 任何行为变更先在 Python 版验证语义，再在 C 版实现，避免两版分叉；实现与验收全部在 C 侧完成。
- 本仓库不得出现 `.py` 文件或 Python 依赖（含测试脚本、生成脚本、打包脚本）。
- 共享资产（图标、键位方案、清单缓存格式）以 Python 版为准，C 版只读生成物。
