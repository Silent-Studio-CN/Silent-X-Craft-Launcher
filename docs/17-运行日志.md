# 运行日志(从 SXCL 启动那一刻起,选择性记录)

> 一句话:**留下能定位问题的行,不留刷屏的行**。文件是必须的(用户报障时我们手上要有东西),
> 同时按平台走 stderr(桌面)/ logcat(安卓,tag `sxcl`)。模块:`include/sxcl/log.h` + `src/core/log.c`。

## 0. 为什么要有这一层(现状是实测出来的)

| 现状 | 后果 |
| --- | --- |
| 追踪大量用 `fprintf(stderr)` | **安卓上 stderr 不进 logcat**(实测 `adb logcat -s sxcl-ui` 是空的),真机排查只能靠"清单缓存字节数/控件几何"这类间接读数 |
| `uiTrace()` 只在 `SXCL_UI_TRACE=1` 时输出 | 默认什么都没留;没有级别、没有文件、没有时间戳规范 |
| 没有轮转 | 开了就刷爆控制台;要留档就得让用户一直开着终端 |

这一层把三件事一次解决:**有文件**、**有级别**、**有限量**(单文件上限 + 保留份数)。

## 1. 通道与格式

| 项 | 值 |
| --- | --- |
| 级别 | `error` < `warn` < `info` < `debug`;默认 **info**;`off` 全关 |
| 文件 | `<配置目录>/logs/sxcl-YYYYMMDD-HHMMSS.log`(配置目录口径 = `sxcl_settings_default_dir`;`SXCL_CONFIG_DIR` / `SXCL_LOG_DIR` 可改) |
| 单文件上限 | 默认 **8 MiB**(`SXCL_LOG_MAX_BYTES` / 设置键 `log.max_bytes`) |
| 保留份数 | 默认 **10**(含当前这份;写满换新文件并把最旧的删掉,`SXCL_LOG_KEEP` / `log.keep`) |
| 终端 | 桌面 stderr(默认开,`SXCL_LOG_STDERR=0` 关);安卓 logcat,tag **`sxcl`** |
| 行格式 | `YYYY-MM-DD HH:MM:SS.mmm LEVEL module \| message`(模块是稳定短键,<=16 字符) |
| 线程安全 | 每行一次 `fwrite`(整行原子)+ 内部锁;多工作线程可同时写 |
| 降级 | 目录/文件打不开、磁盘满、写失败 -> **静默降级**(只丢日志),丢弃条数在 `sxcl_log_stats.dropped` |

模块键(`module`)固定这几个:`startup` / `paths` / `net` / `install` / `launch` / `ui` / `error`。

## 2. 记什么(明确清单)

### 2.1 `startup` —— 启动(进程一起来就记)

| 记什么 | 字段 | 级别 |
| --- | --- | --- |
| 版本号 / 构建时间 | `版本=0.1.0 构建=<__DATE__> <__TIME__>` | info |
| 平台 | `平台=<prettyProductName> 内核=<kernelType>/<arch> 内存=<MB> 逻辑核=<n> pid=<pid> 命令行参数=<n>` | info |
| 日志自身 | 文件全路径 + 上限 + 保留份数(打不开时附人话原因) | info |
| 设置文件路径 | `设置文件=<配置目录>/settings.conf` | info |
| 游戏目录 | `游戏目录=<dir>(选择依据:<为什么选了它>)` —— 六条依据:环境变量钉死 / 设置项 / 安卓私有目录 / 安卓扫描命中(含版本数与来源)/ 安卓退回私有 / 平台默认 | info |
| 主题 / 语言 | `主题=深色(mode=dark) 强调色=#0067c0 语言=zh-CN QSS=<n> 个文件`、语言表条数、Qt 版本 | info |
| 检测到的 Java 列表 | 每个:`Java[i] major=<n> version=<v> 64bit=<0/1> 来源=<JAVA_HOME/PATH/...> 路径=<p>`;一个都没有时给一条 warn | info |
| 界面就绪 / 退出 | `进入事件循环(路由=...)`;退出时 `日志行数 / 字节 / 轮转 / 丢弃 / 文件` | info |

Java 那一步是**只读文件系统**的扫描(`sxcl_java_discover`,不执行 java),所以放在启动路径上不会拖慢窗口。

### 2.2 `net` —— 网络

| 记什么 | 字段 | 级别 |
| --- | --- | --- |
| 控制面请求(取清单 / 版本 JSON / 加载器列表 / JRE 清单 / 登录) | `方法 URL(打码) -> 状态码 字节数 耗时ms 失败原因` | info |
| 下载候选路失败 | `候选 #N 连接失败/状态码不对/太慢/校验失败 url=<打码> \| 原因` | debug |
| 每个文件的请求(Qt 传输层总口) | `方法 URL(打码) -> 状态码 字节数 耗时ms range=<起>` | debug |
| 拿不到响应(连响应头都没有) | `warn`,附 Qt error 码与人话 | warn |

打码规则见 `sxcl_log_mask_url`:查询串里 `access_token / refresh_token / code / client_secret / sig / key / secret / x-amz-*` 等参数的值一律换成 `***`,超长 URL 截断并标注原始长度。**日志里不存在令牌/授权码明文的第二份**。

### 2.3 `install` —— 安装

| 记什么 | 字段 | 级别 |
| --- | --- | --- |
| 计划(开始前) | 游戏目录 / 版本 / 实例 / 加载器 / 资产级别 / 安装器 URL | info |
| 下载参数 | 下载源、`prefer_mirror`、workers、限速、单文件连接数、哈希缓存路径 | info |
| 阶段开始 | `阶段开始 <i>/<n>:<中文名>(<稳定 id>) 整体 <p>% 文件 <a>/<b>` | info |
| 阶段结束 | 由**下一个阶段开始**或下面的终态行表示(阶段表只认核心库那一份) | info |
| 终态(成功) | `安装成功:实例 阶段数 跳过文件 非致命失败 字节` | info |
| 终态(取消) | `安装已取消:实例 阶段 已完成字节` | warn |
| 终态(失败) | `安装失败:码 失败阶段 <i>/<n>(<名字>) 原因=<人话> 可重试 跳过 失败文件 字节` | error |
| 未开始就失败 | 参数不全 / 加载器没直链 / 缺 Java / 没有传输后端 —— 每条都有人话原因 | error |

### 2.4 `launch` —— 启动游戏

| 记什么 | 字段 | 级别 |
| --- | --- | --- |
| 选中的 Java | `选中 Java:<path>(major/version/位数) 游戏目录 版本 内存` | info |
| 身份 / 后端 | 正版(令牌已打码,不落日志)/ 离线;请求后端 -> 实际后端;natives 个数 | info |
| 打码后的命令行 | 逐条 `argv[i]=...`(**核心库自己打的、accessToken 已换成 `***` 的那一份**;本层不拼、不改) | info |
| 进程 | `游戏进程已启动 pid=<pid>`;用户点结束时 `按用户请求结束游戏进程 pid=<pid> rc=<rc>` | info / warn |
| 终态 | `游戏结束:退出码 用时 日志行数 归类=<稳定键>(<人话结论>) 成功/取消/超时/被终止` | info |
| 准备失败 / 运行失败 | `启动准备失败 rc 原因 Java 游戏目录`、`启动失败 rc 退出码 用时 已起进程 原因` | error |

### 2.5 `error` —— 错误(与界面报告**共用同一份上下文**)

`reportUiError()` 里组报告用的就是 `UiErrorContext`(页面 / 操作 / 原因 / 详情),日志从**同一个结构**取字段,不另写第二份:

* `error` 级:一行摘要 `页面= 操作= 原因= 详情= 已复制= 重复=`;
* `debug` 级:剪贴板报告全文,逐行前缀 `报告 \| `(级联上下文能整段贴出来,又不毁掉"一行一条")。

### 2.6 `ui` —— 界面追踪

`uiTrace()` 的每一行**同时**进日志(debug 级),模块键直接取行首的 `<mod> \| `(`install/launch/win/task/versions/…`)。
这是安卓那条"stderr 不进 logcat"老问题的正面解法:同一份追踪现在有 logcat 与文件两条出路。

## 3. 不记什么(有意排除,以及排除在哪一层)

| 不记 | 为什么 | 排除位置 |
| --- | --- | --- |
| **每个文件的逐条下载明细** | 一次装机上千个文件,记下来就把真正有用的行淹了 | 默认 INFO 不记;Qt 传输层与下载引擎里那些行都是 **debug** 级(`SXCL_LOG_LEVEL=debug` 才落盘) |
| **每秒刷屏的进度**(阶段百分比 / 速度 / 剩余 / 当前文件) | 10 次/秒 x 整个安装过程 = 几万行,回答不了任何问题 | 界面照旧每 100ms 更新;日志只在阶段**切换**时记一行 info,细粒度那行是 debug |
| **Qt 内部噪声**(`qWarning`/`qDebug`/平台插件提示) | 不是我们的信息,量还大 | **没有**安装 `qInstallMessageHandler`,Qt 的消息一个字都不进日志 |
| **令牌 / 授权码明文** | 用户会把日志发出来 | URL 打码 `sxcl_log_mask_url`;命令行用核心库打码后的那份;登录令牌只有 `sxcl_auth_mask_token` 的前缀形式 |
| 游戏自己输出的每一行 | 那是游戏日志,不是启动器日志 | 只记归类结论与日志行数;原始行在 debug 级(经 `uiTrace`) |
| 用户隐私路径以外的东西(账户邮箱 / 令牌) | 同上 | 日志里只有 UUID/玩家名这类启动必需字段(来自启动请求),token 不落 |

## 4. 开关一览

| 开关 | 作用 |
| --- | --- |
| `SXCL_LOG_LEVEL=error\|warn\|info\|debug\|off` | 级别(默认 info) |
| `SXCL_LOG_DIR=<目录>` | 日志目录(默认 `<配置目录>/logs`) |
| `SXCL_LOG_MAX_BYTES=<字节>` | 单文件上限(验收用它可以几秒看到轮转) |
| `SXCL_LOG_KEEP=<份数>` | 保留份数(默认 10) |
| `SXCL_LOG_STDERR=0/1` | 桌面是否同时打 stderr |
| 设置文件 `log.level` / `log.max_bytes` / `log.keep` | 不改环境也能开 debug(设置开关;环境变量优先) |
| `SXCL_UI_TRACE=1` | 仍旧把 `uiTrace` 打到 stderr(与日志无关,两条通道都在) |
| `SXCL_NET_DEBUG=1` | Qt 传输层的原始请求/响应头打印(调试用,与日志模块无关) |

## 6. 取日志的办法

* 桌面:日志在 `%APPDATA%\SilentXCraftLauncher\logs\`(Linux/macOS 见 `sxcl_settings_default_dir`),
  或直接看启动时那行 `日志文件=...`;
* 安卓:`adb logcat -s sxcl`(日志模块与 stdio 转发都是这个 tag);文件在同目录的应用私有 `files/SilentXCraftLauncher/logs/`。

### 7.3 轮转(上限调小跑两次)

```powershell
$env:SXCL_LOG_MAX_BYTES = "600"; $env:SXCL_LOG_KEEP = "3"
# 同一个 SXCL_LOG_DIR 连跑两次
```

```text
--- 第 1 次跑完 ---
  sxcl-20260921-165539-2.log  559 字节
  sxcl-20260921-165539.log    527 字节
  sxcl-20260921-165541.log    230 字节
--- 第 2 次跑完 ---
  sxcl-20260921-165541-3.log  559 字节
  sxcl-20260921-165541.log    230 字节
  sxcl-20260921-165543.log    230 字节
文件数 = 3
最新文件 sxcl-20260921-165543.log 行数=1
```

判据:① 每个文件都 <= 600 字节(上限生效);② 目录里**始终只有 3 个**文件(保留份数,含当前这份);③ 跨进程也生效(第二次跑完仍然是 3 个,最旧的被删);④ 当前文件不会被自己删掉(退出汇总那行就写在它自己声明的文件里:末尾那行 `文件=...\sxcl-20260921-165541-3.log` 确实存在于该文件中,`轮转=2` 说明这一次跑里换了 2 次文件)。
